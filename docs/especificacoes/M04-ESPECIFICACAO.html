1. Decisão curricular

O M04 ensina documentação como artefato de engenharia com dois leitores: humano e agente. O agente lê tudo, obedece com confiança e não tem colega para perguntar — por isso doc ausente vira invenção e doc desatualizada vira erro confiante. O módulo cobre taxonomia e contexto, diagrama como código, ADR/postmortem e manutenção automatizada com verificação executável.

Python 3.14 é a linguagem canônica. O laboratório é um verificador de documentação (design_guard) com fixtures locais: ADR lint, checagem de diagramas, detecção de drift e fitness functions de estrutura. Nenhum serviço externo, conta ou rede é requisito. A integração no Capstone (capstone/docs/) ocorre somente após especificação própria do Capstone; neste módulo, o produto é o gabarito + o verificador, exercitados sobre um diretório de demonstração local.

3. Arquitetura do laboratório

docs de demonstração (demo_docs/)
        │
        ▼
design_guard ──► ADR lint (seções, status, "porque")
             ──► referências (caminhos citados existem)
             ──► mermaid (cerca, tipo conhecido)
             ──► obsolescência (git: doc parada, código andou)
             ──► fitness (cobertura de decisão por área)
        │
        ▼
exit code (0 limpo / 1 violação) + relatório

A referência fica em modulos/M04-design-docs-com-ia/lab/. O roteiro Laboratório guiado M04, no final do HTML, cria cópia de trabalho em diretório temporário possuído pelo laboratório.

7. Panorama de prática vigente

Arquivos de instruções de repositório (AGENTS.md/CLAUDE.md) e diagramas Mermaid renderizados no GitHub são prática observável em 2026 — sustentam a decisão didática de ensinar esses formatos. Não provam qualidade de doc nem autorizam recomendação universal de ferramenta.
