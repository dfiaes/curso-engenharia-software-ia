### 1. Google torna MCP ou CLI o canal obrigatório para agentes de IA no Workspace

**O que aconteceu.** Segundo a Help Net Security de 26/11, que resume um post do Google Cloud assinado por Chandu Thota e Brad Calder (não aberto nesta execução), o novo "Workspace AI Tools Addendum" exige que agentes de IA acessem o Workspace pelos servidores MCP ou pelo CLI do Workspace; a aplicação técnica começa em 1/2/2027 e a cobrança ligada a cotas, em 1/4/2027. Apps convencionais podem continuar na REST API. Os servidores MCP cobrem Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat e Tasks (Keep planejado) e checam cada requisição contra permissões, DLP e rótulos de classificação; o CLI usa OAuth com escopo para agentes locais. Agentes externos precisam de client ID OAuth dedicado; operações sensíveis (enviar e-mail, mudar compartilhamento no Drive, edição em massa) exigem confirmação do usuário. O adendo proíbe armazenar dados brutos do Workspace de forma permanente, usá-los para treino e raspar a API sem autorização, e limita a 30 dias a retenção de "Google Technical Information" (embeddings, índices de memória, perfis de usuário, grafos da organização), que deve ser apagada quando a integração é revogada. No lado Cloud, a matéria cita identidade por agente no Agent Registry e o Agent Gateway com saída negada por padrão e Model Armor contra injeção de prompt.

**Por que importa para você.** Se você tem um agente, um RAG ou uma automação que lê Gmail ou Drive pela REST API, o prazo é real e curto: três meses. E a regra de 30 dias atinge exatamente o que times de RAG costumam guardar para sempre: o índice vetorial e a memória derivada. É também o primeiro grande fornecedor a usar MCP como ponto de controle obrigatório, não como conveniência.

**Como aplicar.** Faça o inventário agora: quais integrações suas são "agente" no sentido do adendo e chamam Workspace pela REST API. Para cada uma, planeje a troca para o servidor MCP ou o CLI, crie um client ID OAuth próprio e reduza escopos. No seu store vetorial, adicione TTL de 30 dias (ou reindexação periódica) para conteúdo vindo do Workspace e um job que apague tudo quando o token for revogado. Leia o post original do Google antes de decidir: os termos acima vêm de um resumo.

Fonte: [Help Net Security, 26/11](https://www.helpnetsecurity.com/2026/11/26/google-ai-agent-security-requirements/); post citado: [Google Cloud, Deploying agents safely in your enterprise](https://cloud.google.com/blog/products/identity-security/deploying-agents-safely-in-your-enterprise) (não aberto)

### 2. Antes de migrar para MCP: os avisos de novembro em server-everything, SDK TypeScript e FastMCP

**O que aconteceu.** O resumo de segurança MCP da Adversa, publicado em 09/11 (fora da janela de 24 h, sem cobertura anterior neste diário), reúne avisos GHSA: `@modelcontextprotocol/server-everything` com transporte HTTP ligado em todas as interfaces, CORS curinga, sem autenticação e uma ferramenta `get-env` que devolvia todo o `process.env` (GHSA-mvf5-2qqv-rg3c, corrigido em 2.0.1); `@modelcontextprotocol/server` (SDK TypeScript) 2.0.0 a 2.2.0 casando respostas só pelo id JSON-RPC, o que permitia respostas cruzarem clientes em transporte compartilhado (GHSA-jm63-cq47-j5jp, corrigido em 2.3.0, que recusa transporte compartilhado; stdio não afetado); FastMCP sem vincular o issuer nos provedores OAuth de client credentials e private key JWT, permitindo enviar o segredo a um servidor de autorização do atacante (GHSA-vqqp-x5qm-5qp4; 4.1.2 mais o novo parâmetro `issuer` e rotação de credenciais); Basic Memory com DNS rebinding em SSE sem auth (GHSA-4gfv-c2mm-mvj2, atualizar para 0.24.0; o `HostOriginGuardMiddleware` do FastMCP vem desligado por padrão); e Envoy AI Gateway com seed padrão `default-insecure-seed` no Helm, que torna IDs de sessão MCP forjáveis (GHSA-953h-535j-jg2v, 1.2.0-rc1).

**Por que importa para você.** O padrão se repete: servidor MCP local exposto por HTTP vira alvo de qualquer página aberta no navegador (CORS curinga, DNS rebinding), e servidor HTTP compartilhado entre clientes precisa isolar sessão. Quem expõe MCP por HTTP para um time está exatamente nessa superfície.

**Como aplicar.** Rode `npm ls @modelcontextprotocol/server @modelcontextprotocol/server-everything` e `pip show fastmcp basic-memory` nos seus projetos e atualize para as versões acima. Servidor de desenvolvimento por HTTP: ligue só em `127.0.0.1`, exija token e ative validação de Host/Origin. No FastMCP com OAuth, configure `issuer` e troque o segredo do cliente. No Envoy AI Gateway, confira se o seed do Helm não é o padrão.

Fonte: [Adversa, Top MCP security resources, novembro 2026 (09/11)](https://adversa.ai/blog/top-mcp-security-resources-november-2026/)
