### 1. Codex CLI 0.169.0: confiança no diretório separada do sandbox

**O que aconteceu.** Segundo o changelog reproduzido pelo gradually.ai (conferido com a fonte oficial em 14/11), o Codex CLI teve duas versões em 13/11. Na 0.169.0, `codex exec` mantém a configuração do projeto e os servidores MCP desligados em diretórios não confiáveis, mesmo com `--sandbox workspace-write`; `--trust` em `codex exec` ou `codex review` grava a confiança do projeto. Também: abas de side chat no workspace de terminal, busca de tarefas antigas na central de agentes, cadastro de provedores de modelo customizados pelo terminal (com device code para gateways via SSH), "Yes, clear context and implement" que passa o plano aprovado para uma sessão nova, e Ctrl+S para salvar ZIP de diagnóstico local. A 0.168.0 trouxe painel lateral (`features.tui_workspace`), escolha de provedor padrão e aviso quando `features.multi_agent` ainda está setado (o substituto é `agents.enabled`).

**Por que importa para você.** Em CI, o agente costuma rodar num clone recém-criado, ou seja, num diretório não confiável. Se o seu pipeline dependia de um MCP ou config declarado no repositório, ele para de carregar depois da atualização. É o comportamento certo: um PR de fork poderia trazer um MCP malicioso.

**Como aplicar.** Atualize num job de teste e confira se os MCPs do projeto aparecem. Se precisa deles, use `--trust` só em pipelines que rodam código do próprio repositório (branch protegida), nunca em jobs disparados por PR de fork. Se usa `features.multi_agent`, troque por `agents.enabled`.

Fonte: [gradually.ai, changelog Codex CLI](https://www.gradually.ai/en/changelogs/codex-cli/) (agregador); [GitHub, rust-v0.169.0](https://github.com/openai/codex/releases/tag/rust-v0.169.0) (não aberto)

### 2. llama.cpp v1.0.0: API e ABI estáveis

**O que aconteceu.** O llama.cpp chegou à v1.0.0 com API e ABI estáveis para quem usa a biblioteca; novos majors só quando houver quebra, segundo o RIO Rundown (14/11), que cita o blog do ggml-org no Hugging Face. O resumo lista suporte a NVIDIA, AMD, Qualcomm, Arm, IBM e Intel e CI melhorado. Data exata do lançamento não informada no agregador.

**Por que importa para você.** Bindings (llama-cpp-python, wrappers .NET) e runtimes que embutem o llama.cpp sofriam com mudanças de API entre builds. Versionamento semântico permite fixar `1.x` com segurança e atualizar sem reescrever a integração.

**Como aplicar.** Se você compila ou embute o llama.cpp, leia o post original antes de atualizar e confira se o seu binding já declara compatibilidade com a 1.0. Fixe a versão por número no seu manifesto (Homebrew, `pyproject.toml`, Dockerfile) em vez de "latest" e meça tokens/s no seu modelo antes e depois.

Fonte: [RIO Rundown, 14/11](https://riorundown.substack.com/p/ai-news-nov-14-2026-local-ai-ecosystem) (agregador); [Hugging Face, llama.cpp v1](https://huggingface.co/blog/ggml-org/llama-cpp-v1) (não aberto)

### 3. ChatGPT Wallet: o agente paga, você aprova cada compra

**O que aconteceu.** A OpenAI lançou em 13/11 o ChatGPT Wallet: os agentes "dots" pagam com um token no lugar do número real do cartão, depois que o usuário revisa e aprova com digital ou rosto. Primeiro para assinantes ChatGPT Pro nos EUA, maiores de 18, com cartão americano elegível; feito com American Express, Mastercard e Visa, com Forter, Riskified, Sardine e Signifyd na antifraude. Compra delegada com limite de gasto e categoria fica para depois, segundo o This is not Average e o AI Impact Hub. No mesmo dia, a United disse que vai restringir agentes pessoais de terceiros nos sistemas de reserva, citando risco de credencial compartilhada, compras não intencionais e regras de aviação que exigem humano em certos passos (AI Agent Store, sem link primário).

**Por que importa para você.** As duas notícias mostram o desenho que está se firmando: agente age com credencial própria e escopo limitado (token de pagamento), e cada ação com efeito externo passa por aprovação humana forte. O caminho oposto, agente usando login e senha do usuário, está sendo bloqueado pelos próprios sites.

**Como aplicar.** Se o seu agente executa ações com dinheiro ou dados de terceiros, revise: ele usa credencial própria com escopo e validade curta, ou a do usuário? Há aprovação por ação, registrada com quem aprovou? Se você expõe API para agentes de clientes, decida agora como identificá-los (token delegado, não senha compartilhada).

Fonte: [This is not Average, 14/11](https://kellyabbott1.substack.com/p/ai-frontier-daily-2026-11-14) (agregador); [AI Impact Hub, 15/11](https://www.aiimpacthub.com/ai-news/2026-11-15) (agregador); [AI Agent Store, semana de 15/11](https://aiagentstore.ai/ai-agent-news/this-week) (agregador); [OpenAI, ChatGPT Wallet](https://openai.com/index/introducing-chatgpt-wallet/) (não aberto)

### 4. Cloudflare Kitesurf: navegador para agentes sem contêiner Chromium

**O que aconteceu.** A Cloudflare abriu o código do Kitesurf em 13/11, sob Apache 2.0: um motor de navegador que roda dentro do Workers, interpreta HTML, executa o JavaScript da página e tira screenshots sem contêiner Chromium, usando WebAssembly. Fala Chrome DevTools Protocol, então o Puppeteer conecta sem mudança. Implantação pública exige plano Workers Paid e autenticação própria, porque o Kitesurf não traz nenhuma, segundo o This is not Average e o AI Agents Directory.

**Por que importa para você.** Ferramenta de navegação é das mais caras e frágeis de um agente (contêiner pesado, cold start). Um motor leve compatível com CDP muda o custo. Sem autenticação embutida, um deploy descuidado vira proxy aberto que executa JavaScript arbitrário.

**Como aplicar.** Se você tem ferramenta de navegação via Puppeteer, aponte um teste para o Kitesurf e compare fidelidade nas páginas que o seu agente realmente visita (SPA, login, cookies). Antes de expor, ponha autenticação e lista de domínios permitidos na frente.

Fonte: [This is not Average, 14/11](https://kellyabbott1.substack.com/p/ai-frontier-daily-2026-11-14) (agregador); [AI Agents Directory, 14/11](https://aiagentsdirectory.com/news/ai-agents-news-brief-2026-11-14) (agregador); [Cloudflare blog, Kitesurf](https://blog.cloudflare.com/kitesurf-open-source/) (não aberto)
