### 1. Gemini API ganha Tool Retrieval: esquema da ferramenta só entra no contexto quando é preciso

**O que aconteceu.** Em 19/11 o Google pôs em preview, só na Interactions API, o Tool Retrieval. Você adiciona `{"type": "tool_search"}` ao array `tools` e marca `"defer_loading": true` nas ferramentas que quer adiar; o modelo continua vendo nome e descrição de cada uma e carrega o esquema de parâmetros quando a tarefa pede. Os passos aparecem em `interaction.steps` como `tool_search_call`, `tool_search_result` e `function_call`. `defer_loading` num `mcp_server` adia todas as ferramentas daquele servidor. Há modo cliente (`"execution": "client"`), em que sua aplicação devolve os esquemas num `function_result`, com uma ida e volta a mais por busca. Não há cobrança separada, mas ligar o `tool_search` soma um bloco fixo de tokens de entrada, e cada esquema carregado é cobrado como entrada pelo resto da conversa. O post não traz número de economia nem data de GA. Segundo a PPC Land, citando a documentação: cerca de 26 tokens por ferramenta adiada; cada busca no servidor é uma passada extra do modelo, contada em `total_tool_use_tokens`; esquema carregado não pode ser descarregado; o array `tools` inteiro precisa ir em toda requisição, mesmo com `previous_interaction_id`; uma busca sem resultado devolve texto, não erro estruturado; modos servidor e cliente não se misturam na mesma requisição. O post fala em "Gemini 3.6 e posteriores, incluindo todos os Gemini 4"; a documentação, segundo a PPC Land, lista só `gemini-3.6-flash`, `gemini-3.8-flash`, `gemini-4-argon` e `gemini-4-hydrogen`, e outros modelos devolvem 400.

**Por que importa para você.** Com isto, Anthropic, OpenAI e Google usam o mesmo nome de parâmetro (`defer_loading`) para o mesmo padrão. Um agente com dezenas de ferramentas MCP deixa de pagar todos os esquemas a cada turno, mas troca isso por uma passada a mais por busca e por um contexto que só cresce. Se a descrição da ferramenta for ruim, a busca não a encontra: a descrição vira a interface.

**Como aplicar.** Meça antes de adotar: rode a mesma tarefa com e sem `defer_loading` e compare tokens de entrada, `total_tool_use_tokens` e acerto na escolha da ferramenta. Deixe fora do adiamento as 3 a 5 ferramentas usadas em quase todo turno e as citadas no system prompt. Reescreva as descrições das ferramentas adiadas para dizer quando usá-las, não só o que fazem, e teste o caso de busca sem resultado, que chega como texto.

Fonte: [Google, Introducing Tool Retrieval in the Gemini API, 19/11](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/); [PPC Land, 19/11](https://ppc.land/google-shrinks-idle-tools-in-gemini-agents-to-about-26-tokens-each/)

### 2. Ollama 0.40.17: requisições em paralelo no Apple Silicon e ferramentas adiadas no Claude Code

**O que aconteceu.** A versão 0.40.17, de 21/11 segundo o Releasebot, traz: o Inkling 2 Mini (`ollama run inkling-2-mini`, só Apple Silicon nesta versão); atendimento de várias requisições ao mesmo tempo no Apple Silicon; suporte ao carregamento adiado de ferramentas do Claude Code em `ollama launch claude`; `ollama launch opencode` configurando o raciocínio a partir dos metadados do modelo; desligar o thinking passa a mapear para o menor nível de raciocínio que o modelo suporta; mudar o context shift deixa de recarregar o modelo; definições de ferramenta na API preservam palavras-chave de JSON Schema; builds a partir do código podem usar binários prontos de MLX-C e XGrammar.

**Por que importa para você.** No M3 Max, o caso comum é o mesmo modelo servindo editor, agente e script ao mesmo tempo; antes as chamadas faziam fila. E o Claude Code apontado para modelo local passa a carregar só as ferramentas que usa, o que pesa mais num modelo de 20 a 30B com contexto curto do que num modelo de nuvem.

**Como aplicar.** Atualize (`ollama --version` deve mostrar 0.40.17) e rode dois clientes em paralelo contra o mesmo modelo para ver a latência de cada um; a nota não diz quantas requisições simultâneas cabem nem como configurar, então confira a documentação antes de mexer em variáveis. Se você usa `ollama launch claude`, compare o tamanho do primeiro prompt antes e depois da atualização.

Fonte: [Releasebot, notas do Ollama](https://releasebot.io/updates/ollama) (agregador das notas oficiais)
