1. Claude Code: "Yes, and don't ask again" pode salvar senhas no repositório

O que aconteceu. A Cyber Security News publicou em 07/11 a pesquisa da Apiiro (coleta de 01 a 03/11/2026): ao aprovar um comando de shell com "Yes, and don't ask again", o Claude Code salva o comando inteiro, incluindo qualquer segredo embutido, como regra de allow em .claude/settings.local.json. Se esse arquivo for commitado em repositório público, o segredo vaza. Segundo o artigo, a Apiiro examinou 104.185 cópias públicas desse arquivo, achou segredos reais em 1.122 e, somando histórico de commits, settings.json compartilhados e transcrições de agente, chegou a 2.539 segredos distintos em 1.994 repositórios (63 organizações), entre eles 379 senhas de banco, 122 chaves service-role do Supabase e 43 logins SSH. Gitleaks marcou 564 dos 1.122 arquivos, TruffleHog 643, e nenhum dos dois marcou 215. O Claude Code adiciona uma exclusão ao gitignore global na primeira escrita, mas, segundo o artigo, isso não viaja com o projeto, não cobre arquivos já rastreados e não protege de forma confiável uma pasta que vira repositório depois. Nenhuma versão do Claude Code é citada; o artigo diz que um issue no GitHub já relatava o armazenamento em texto puro em agosto de 2025.

Por que importa para você. Não é ataque: é o fluxo normal de aprovação. Todo agente de código que persiste permissões cria um arquivo de configuração com conteúdo derivado de comandos, e os scanners de segredo padrão não pegam tudo.

Como aplicar. Hoje, em cada repositório onde você usa o Claude Code:

git log --all --oneline -- .claude/settings.local.json   # já foi commitado?
grep -nE 'password|token|secret|Bearer|postgres://' .claude/settings*.json
git rm --cached .claude/settings.local.json && echo '.claude/settings.local.json' >> .gitignore

Se achar segredo, rotacione antes de limpar o histórico. Daqui em diante, passe credenciais por variável de ambiente ou gerenciador de segredos, nunca literais no comando que você aprova, e inclua .claude/ no escopo do secret scanning do time.

2. Codex CLI 0.167.0: central de agentes no terminal

O que aconteceu. O changelog da OpenAI registra o Codex CLI 0.167.0 em 06/11: uma central de agentes (codex agents --no-daemon) que marca resultados não lidos; troca entre backends conectados pelo seletor de sessão, mantendo rascunhos; prévia de imagens locais ao compor; configuração do Google Cloud Vertex AI pelo assistente de login; opção experimental de usar o proxy do sistema no macOS e no Windows; e detalhes do patch expandidos enquanto o prompt de aprovação está aberto.

Por que importa para você. Duas mudanças são de fluxo: acompanhar vários agentes em paralelo sem perder resultados e ver o patch completo antes de aprovar, o que reduz aprovação às cegas.

Como aplicar. Atualize o CLI, rode codex agents --no-daemon com duas tarefas pequenas em paralelo e confira se o painel de não lidos substitui o seu vaivém entre terminais. Em rede corporativa, teste a opção de proxy do sistema em /experimental antes de configurar proxy manualmente.

Revisão rápida

1. Segundo o relato da pesquisa da Apiiro, qual é a primeira resposta ao descobrir um segredo commitado em .claude/settings.local.json?
  1. Revogar e rotacionar a credencial antes de apagar o arquivo ou reescrever o histórico (correta)
  2. Rodar git rm e forçar push para limpar o histórico
  3. Tornar o repositório privado

O segredo já pode ter sido copiado; apagar o arquivo não invalida a credencial. Rotação primeiro, limpeza depois.

2. Por que a exclusão que o Claude Code adiciona ao gitignore global não basta?
  1. Ela não viaja com o projeto e não cobre arquivos que já estavam rastreados (correta)
  2. Ela só funciona no Windows
  3. Ela ignora apenas .env

O gitignore global vale só na máquina de quem o tem; um clone em outra máquina ou um arquivo já rastreado continua sendo commitado.
