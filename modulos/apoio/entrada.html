Terminal, comando e retorno

O terminal recebe comandos e mostra texto produzido por programas. O shell é o programa que interpreta o que você digita; no roteiro do curso, o shell canônico é Windows PowerShell. O shell inicia outro processo, como o interpretador Python, e entrega a ele os argumentos.

py -3.14 .\ler_resumo.py .\relatorio.json

Neste comando, py inicia Python, -3.14 seleciona essa versão no launcher do Windows, .\ler_resumo.py identifica o arquivo do programa e .\relatorio.json é um dado que o programa vai ler. O ponto inicial significa “a pasta atual”. Se o launcher py não estiver instalado, use o comando python configurado para Python 3.14.

A pasta atual (working directory) é o diretório no qual o shell está posicionado. Ela influencia caminhos relativos como .\relatorio.json. Em PowerShell, Get-Location mostra essa pasta.

Um processo escreve mensagens normais em stdout e diagnósticos em stderr. Quando termina, ele também devolve um número chamado código de saída: por convenção, zero significa que a operação terminou como esperado; valor diferente de zero sinaliza que não terminou normalmente. O código não explica o motivo sozinho — a mensagem de erro completa esse diagnóstico.

Um programa completo

Este pequeno utilitário recebe um caminho, lê um objeto JSON e imprime um resumo. Só usa a biblioteca padrão incluída com Python. O arquivo mostrado no primeiro bloco é entrada de exemplo; o segundo é o programa.

Arquivo de dados: relatorio.json

{
  "projeto": "Cartografo",
  "etapas": ["API", "avaliacao"]
}

Programa: ler_resumo.py

import json
import sys
from pathlib import Path
from typing import Any


def carregar_objeto(caminho: Path) -> dict[str, Any]:
    """Lê UTF-8 e exige um objeto JSON na raiz do arquivo."""
    try:
        valor: Any = json.loads(caminho.read_text(encoding="utf-8"))
    except (OSError, UnicodeDecodeError, json.JSONDecodeError) as erro:
        raise ValueError(f"não foi possível ler {caminho}: {erro}") from erro

    if not isinstance(valor, dict):
        raise ValueError("a raiz do JSON precisa ser um objeto")
    return valor


def texto_obrigatorio(dados: dict[str, Any], chave: str) -> str:
    """Obtém um campo textual e rejeita ausência ou conteúdo em branco."""
    valor = dados.get(chave)
    if not isinstance(valor, str) or not valor.strip():
        raise ValueError(f"o campo {chave!r} precisa conter texto")
    return valor


def main(argumentos: list[str]) -> int:
    if len(argumentos) != 2:
        print("uso: py -3.14 .\\ler_resumo.py .\\relatorio.json", file=sys.stderr)
        return 2

    caminho = Path(argumentos[1])
    try:
        dados = carregar_objeto(caminho)
        projeto = texto_obrigatorio(dados, "projeto")
        etapas = dados.get("etapas", [])
        if not isinstance(etapas, list) or not all(isinstance(item, str) for item in etapas):
            raise ValueError("etapas precisa ser uma lista de textos")
    except ValueError as erro:
        print(f"erro: {erro}", file=sys.stderr)
        return 2

    print(f"Projeto: {projeto}")
    for etapa in etapas:
        print(f"- {etapa}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main(sys.argv))

Salve esses dois conteúdos em arquivos com os nomes mostrados, na mesma pasta. A execução abaixo é apenas um exemplo local; este curso não precisa criar um serviço, usar rede ou instalar uma biblioteca adicional para entendê-lo.

Get-Location
py -3.14 .\ler_resumo.py .\relatorio.json
Saída esperada: 
Projeto: Cartografo
- API
- avaliacao
O programa retorna código 0. O nome sai do objeto JSON; cada item de etapas vira uma linha.

Se você omitir o caminho ou enviar um JSON inválido, a mensagem vai para stderr e o programa retorna 2. Um valor diferente de zero não é uma prova automática de defeito: aqui ele indica que a entrada não cumpriu o contrato declarado pelo programa.

As peças do exemplo

FormaSignificado aqui
caminho = Path(...)Uma variável chamada caminho passa a referenciar um objeto que representa a localização de um arquivo. Criar o objeto não lê nem altera o arquivo.
def carregar_objeto(...):Define uma função: um bloco nomeado que pode receber valores, executar passos e devolver um resultado. -> dict[str, Any] anota o tipo esperado do retorno; Python não valida essa anotação automaticamente em tempo de execução.
dados.get("projeto")Consulta um campo do dicionário. Um dict (dicionário) guarda pares chave/valor, como "projeto" → "Cartografo". get devolve None se a chave não existir, em vez de lançar KeyError.
list[str]Uma lista de textos. Colchetes também acessam posições, mas aqui definem um tipo composto: sequência ordenada, possivelmente vazia. Em JSON, o array correspondente vira uma lista Python.
if ...: e indentaçãoExecuta o bloco recuado somente quando a condição é verdadeira. Em Python, a indentação faz parte da estrutura do programa.
return 2Devolve um valor à função que chamou main. O código final só muda porque raise SystemExit(...) passa esse valor ao processo Python.
for etapa in etapas:Percorre os textos em ordem, atribuindo um item por vez à variável etapa. Não precisa consultar índices para ler uma lista.
Path(argumentos[1])O índice 1 seleciona o primeiro argumento depois do nome do programa. Índices começam em zero: argumentos[0] é o próprio nome/caminho do script.

Os comentários entre aspas logo abaixo de uma função são uma docstring: texto de documentação associado ao bloco. Os parênteses chamam uma função; argumentos são os valores enviados. Por exemplo, texto_obrigatorio(dados, "projeto") envia dois argumentos.

Any indica que o resultado vindo do parser JSON ainda pode ter vários tipos. A validação com isinstance confere em tempo de execução que um valor realmente é um dicionário, lista ou texto. Type hints ajudam ferramentas de análise e pessoas leitoras; sozinhos, não rejeitam dados ruins.

JSON: texto com estrutura

JSON é um formato textual para representar objetos e listas que sistemas diferentes conseguem trocar. No exemplo, chaves são textos e valores são texto ou lista. Dentro de um arquivo JSON:

  • texto usa aspas duplas: "projeto";
  • objetos usam chaves {} e arrays usam colchetes [];
  • os literais são true, false e null; em Python tornam-se True, False e None;
  • comentários e vírgula depois do último item não pertencem à sintaxe padrão JSON.

json.loads(texto) converte uma string JSON em valores Python. Objetos viram dicionários, arrays viram listas. json.load(arquivo) cumpre a mesma função lendo um objeto de arquivo; neste exemplo, Path.read_text(encoding="utf-8") lê texto primeiro e torna explícita a codificação.

O parser pode rejeitar sintaxe inválida com JSONDecodeError. Já um arquivo ausente ou sem permissão pode causar OSError; bytes que não formam o texto esperado podem causar UnicodeDecodeError. São problemas diferentes, por isso o programa captura e mostra um diagnóstico em vez de fingir que o arquivo estava vazio.

Limite de confiança. JSON válido significa apenas que a estrutura pode ser interpretada. Ele não prova que campos existem, que os valores têm o tipo certo ou que o conteúdo é verdadeiro. Depois de analisar sintaxe, o programa ainda verifica o contrato local.

Variáveis de ambiente

O processo pode receber pares de texto chamados variáveis de ambiente. Elas são úteis para opções externas ao código, como escolher um perfil local. O processo herda o ambiente do shell que o iniciou; uma variável definida somente na janela atual não é uma configuração global do computador.

$env:APP_PROFILE = "local"
py -3.14 -c "import os; print(os.environ.get('APP_PROFILE', 'nao definido'))"

os.environ oferece essas entradas como um mapeamento parecido com dicionário. get(chave, padrão) lê a chave ou devolve o padrão se ela faltar. O comando -c pede ao interpretador que execute código curto passado como texto; a resposta esperada é local.

O limite importa: variáveis de ambiente não são um cofre. Podem aparecer em ferramentas de diagnóstico ou ser herdadas por processos filhos. O curso não pede que você coloque segredos no exemplo nem que altere o ambiente do sistema.

Git e snapshots

Git registra snapshots versionados do conteúdo e permite comparar o estado atual com um commit. Um commit é um snapshot com identidade e metadados; arquivos modificados ainda não fazem parte dele. Isso deixa revisar diferenças antes de decidir se e quando registrar uma nova versão.

git status --short
git diff
git diff --staged
git show --stat --oneline HEAD
  • git status --short resume arquivos modificados, preparados e ainda não rastreados.
  • git diff mostra mudanças ainda fora da área de preparação.
  • git diff --staged mostra o que está preparado para o próximo commit.
  • git show ... HEAD resume o commit atual.

Esses comandos são leitura. git add prepara mudanças e git commit cria outro snapshot; nenhum dos dois é exigido para continuar lendo um módulo. O conceito de snapshot também não substitui backup nem isola serviços externos como bancos de dados.

SintomaO que conferir
“não foi possível encontrar o arquivo”Confira a pasta mostrada por Get-Location e o caminho relativo enviado ao programa.

o campo projeto precisa conter textoA sintaxe pode ser válida, mas a chave falta, está vazia ou contém outro tipo. Ajuste o contrato ou os dados de forma deliberada.
o terminal não reconhece pyConfira se o launcher existe com py -3.14 --version; use o comando Python 3.14 disponível no ambiente.

Erro é uma observação sobre determinada fronteira: localizar o arquivo, interpretar sua sintaxe, validar seu conteúdo ou executar a lógica. Distinguir essas fronteiras evita trocar código quando a causa está no caminho — ou alterar dados para mascarar um contrato incorreto.
