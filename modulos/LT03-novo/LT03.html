N1 · Cloud: responsabilidade, failure domains, custo

Cloud é acesso por rede a recursos computacionais compartilhados, provisionados sob demanda e medidos por uso. Três ideias separam "servidor alugado" de cloud: o provisionamento é por chamada (não por chamado), a capacidade é elástica dentro de limites (não infinita) e tudo é medido — cada unidade consumida tem preço. A definição canônica de características e modelos é a da fonte normativa do bloco.

Responsabilidade compartilhada é a linha que diz quem opera o quê. IaaS (infraestrutura como serviço) entrega compute, rede e storage crus: o provedor opera o físico e a virtualização; sistema operacional, runtime e aplicação continuam seus. PaaS (plataforma como serviço) sobe a linha: o provedor opera runtime, banco gerenciado, fila gerenciada; você opera código, dado e configuração. SaaS (software como serviço) entrega o aplicativo pronto: você opera identidade, dado e uso. Cada degrau troca controle por operação delegada — e cada delegação tem preço, limite e saída, que precisam constar na decisão (AT-003).

Custo fixo contra variável. Fixo é o que você paga parado: reserva, disco provisionado, endereço, controle. Variável é o que acompanha o uso: CPU-hora, egress, requisições, armazenamento medido. O erro clássico é desenhar como se tudo fosse variável (e descobrir o fixo na fatura) ou como se tudo fosse fixo (e pagar pico o mês inteiro). Portabilidade contra menor denominador comum: cada serviço gerenciado adotado acelera hoje e cobra saída amanhã — formato proprietário, egress de extração, reescrita. A decisão honesta registra responsabilidade, egress e saída por escrito; é a tabela de decisão do AT-003.

Contraste"Está na nuvem, então é elástico e portável" — não. Cloud dá o mecanismo de elasticidade, não a garantia: quota, tempo de inicialização, dependência saturada e custo continuam decidindo o que acontece no pico. E cada serviço gerenciado é uma aposta de permanência: quanto mais específico do provedor, maior o custo de saída. O sintoma que denuncia o erro é conhecido: a fatura cresce junto com o tráfego enquanto a latência não melhora, e ninguém sabe dizer o que cada parte custa nem como sair. O oráculo AT-003 cobra os dois lados: failure domains listados e responsabilidade, egress e saída explícitos.

N2 · A imagem OCI como empacotamento

Imagem OCI é um empacotamento padronizado de tudo que o processo precisa para rodar: filesystem, config de execução e o ponteiro imutável que a identifica. Quatro peças compõem o pacote: camadas (layers), config, manifest e digest. A distribuição (registry) é a prateleira; o índice (index) é a lista que permite várias variantes — por arquitetura — sob um mesmo nome.

PeçaDefinição e mecanismoLimite
Camada (layer)Um tarball de diferenças do filesystem, empilhado sobre as anteriores. Cada instrução de build acrescenta uma camada; camadas idênticas entre imagens são armazenadas e transferidas uma vez.Camada nunca é removida por instrução posterior: arquivo "apagado" depois continua no histórico e no tamanho. Segredo copiado numa camada é segredo publicado, mesmo que removido adiante.
ConfigO documento que diz como executar: arquitetura, sistema, comando padrão, usuário, variáveis, portas declaradas. É parte endereçável da imagem, com digest próprio.Config declara intenção, não impõe: usuário declarado pode ser sobrescrito na execução; a prova está no runtime, não no documento.
ManifestA lista assinável: referencia a config e cada camada pelos seus digests, mais anotações. Inspecionar o manifest é ler a composição exata sem baixar o conteúdo.Manifest descreve uma arquitetura; o multi-arch mora um nível acima, no índice.
DigestO hash do conteúdo (na forma sha256:…): a identidade da imagem. Mesmo byte, mesmo digest; byte distinto, digest distinto. Referenciar por digest é apontar para conteúdo exato.Digest é ilegível por humanos: identifica, não explica. Versão legível e trilha de promoção moram ao lado, nunca no lugar.

PID 1, usuário, filesystem e multi-arch. Dentro do container, o processo principal é o PID 1: pai dos órfãos, destinatário do SIGTERM do runtime (ponte com o LT01-B01 e com a seção N4). O usuário de execução decide o dano alcançável: root no container compartilha o kernel com o host — container não é VM nem fronteira absoluta (regra 2). O filesystem da imagem é a soma das camadas, gravável por padrão; declarar raiz read-only move escrita para volumes explícitos. Multi-arch é o índice apontando uma imagem por arquitetura: o mesmo nome, o digest certo por máquina.

Fundamento de engenharia · Identidade é conteúdo; nome é conveniência. O digest responde "o quê exatamente"; a tag responde "como chamamos hoje". Todo o resto da trilha depende dessa separação: promoção move o mesmo digest entre ambientes, rollback volta ao digest anterior, auditoria cita digest. Cada vez que este bloco exigir digest pinado, é essa troca que está em jogo: legibilidade agora contra reprodutibilidade depois. Tag sem digest registrato é apelido sem identidade.

N3 · Imagem Python mínima, non-root, reproduzível

A imagem do serviço desta trilha segue cinco decisões, cada uma com mecanismo e verificação na folha B01-L:

  1. Base mínima. Partir da variante enxuta do runtime (forma esbelta da distribuição), nunca da imagem completa com toolchain. Menos pacote é menos superfície: cada binário ausente é uma vulnerabilidade a menos e um pull mais curto. A verificação local é heurística (nome da variante); o tamanho real é medido na trilha externa.
  2. Build em estágios. Um estágio monta — instala dependências, compila o necessário — e o estágio final carrega só o artefato: código, ambiente virtual, nada de compilador. O mecanismo é o das camadas: o que fica no estágio descartado não entra em camada alguma da imagem final.
  3. Dependências bloqueadas. Versões exatas registradas em lockfile: o mesmo manifesto resolve o mesmo conjunto hoje e daqui a meses. Sem lock, rebuild é sorteio silencioso.
  4. Usuário non-root. Criar usuário sem privilégio e declarar o USER antes do comando: o processo nunca tem root, nem por acidente de sobrescrita parcial. Verificação estática na folha (último USER declarado); prova no runtime externo.
  5. Dockerfile versionado, sem segredo. O Dockerfile mora no Git, revisado como código: base pinada por digest, sem credencial em instrução alguma, sem arquivo de segredo copiado. Camada com segredo é vazamento permanente, mesmo removida depois.

DecisãoRoot por preguiça, segredo na camada, base flutuante: os três defeitos catalogados da imagem. Container como root converte qualquer escape em controle amplo; segredo em camada converte registry em cofre aberto; base sem digest converte rebuild em roleta. Nenhum dos três aparece como erro no build — todos passam verdes. Por isso a validação é estática e prévia: o oráculo AT-001 lê o Dockerfile antes de qualquer build e recusa os três.

N4 · SIGTERM no container: grace, drenagem, saída

No container, o SIGTERM chega pelo runtime ao PID 1, e o grace period é o tempo contratado entre esse pedido e o SIGKILL imposto. O mecanismo é o do LT01-B01, com uma etapa a mais na frente — a drenagem:

  1. Drenar: parar de receber tráfego novo. O endpoint sai do balanceamento antes de qualquer outra coisa: nenhuma requisição nova é aceita após o sinal. Shutdown que aceita trabalho novo durante o grace é defeito catalogado — cada aceita é uma futura vítima do SIGKILL.
  2. Encerrar ou cancelar o trabalho em curso. Requisições breves concluem; trabalho longo recebe cancelamento cooperativo e libera recursos. Handler que ignora cancelamento desperdiça o grace inteiro.
  3. Sair com o exit code contratado, dentro do prazo. Descarregar, fechar, devolver o código limpo. Morte por SIGKILL registra a morte, não a saída.

Timeline de shutdown (exemplo variável, não evidência). Instante zero: o runtime entrega SIGTERM ao PID 1. O serviço fecha a entrada para tráfego novo e marca o deadline interno — por exemplo, grace de algumas dezenas de segundos contratado com o orquestrador. Requisições breves concluem nos primeiros segundos; o trabalho longo recebe cancelamento e libera recursos; no fim do prazo, o processo sai com o exit code esperado. A folha B01-L registra a timeline real localmente; a prova sob orquestrador real pertence à trilha externa.

Build reproduzível e seus limites honestos. Reproduzível significa: mesmo Dockerfile versionado, mesmo lockfile, mesma base pinada por digest produzem o mesmo digest de imagem. O que a folha local prova: contrato do Dockerfile (AT-001) e comportamento de sinal e grace (AT-002). O que só a trilha externa prova: build, publicação, inspeção de manifest e camadas, execução pelo digest, tamanho e cold start medidos. Onde Docker estiver ausente, esses oráculos nascem BLOCKED com registro — nunca simulados, nunca com número hardcoded.

"""Validacao estatica de Dockerfile: non-root, base minima, digest pinado.

Referencia executavel do Bloco 1.
Implementacao verbatim na folha B01-L. So STDLIB (re).
Nao executa Docker: le texto, publica veredito.
"""

from __future__ import annotations

import re

PADRAO_INSTRUCAO = re.compile(r"^\s*([A-Za-z]+)\s+(.*?)\s*$")
PADRAO_SECRETO = re.compile(r"(senha|secret|token|api[_-]?key|passwd)", re.IGNORECASE)
VARIANTES_MINIMAS = ("slim", "alpine", "distroless")


def instrucoes(texto: str) -> list[tuple[str, str]]:
    """Cada linha valida vira (INSTRUCAO, argumentos); ignora vazias e comentarios."""
    saidas: list[tuple[str, str]] = []
    for linha in texto.splitlines():
        sem_comentario = linha.split("#", 1)[0]
        if not sem_comentario.strip():
            continue
        casa = PADRAO_INSTRUCAO.match(sem_comentario)
        if casa:
            saidas.append((casa.group(1).upper(), casa.group(2).strip()))
    return saidas


def usuario_final(texto: str) -> str | None:
    """Ultimo USER declarado; None se ausente (roda como root)."""
    usuarios = [args.split()[0] for nome, args in instrucoes(texto) if nome == "USER"]
    return usuarios[-1] if usuarios else None


def bases(texto: str) -> list[str]:
    """Toda imagem apos cada FROM, na ordem de declaracao."""
    return [args.split()[0] for nome, args in instrucoes(texto) if nome == "FROM"]


def digest_pinado_na_base_final(texto: str) -> bool:
    """A ultima base referencia conteudo exato via '@sha256:'."""
    lista = bases(texto)
    return bool(lista) and "@sha256:" in lista[-1]


def base_minima(texto: str) -> bool:
    """Heuristica local: a base final nomeia variante enxuta.

    Nao mede tamanho; o tamanho real e medido na trilha externa.
    """
    lista = bases(texto)
    return bool(lista) and any(v in lista[-1].lower() for v in VARIANTES_MINIMAS)


def expoe_segredo(texto: str) -> bool:
    """True se ARG/ENV carrega nome de segredo ou COPY traz arquivo sensivel."""
    for nome, args in instrucoes(texto):
        if nome in ("ARG", "ENV") and PADRAO_SECRETO.search(args):
            return True
        if nome == "COPY" and PADRAO_SECRETO.search(args):
            return True
    return False


def relatorio(texto: str) -> dict[str, object]:
    """Junta as verificacoes; 'aprovada' exige todas as condicoes."""
    usuario = usuario_final(texto)
    vereditos: dict[str, object] = {
        "usuario_final": usuario,
        "nao_root": usuario is not None and usuario != "root" and usuario != "0",
        "bases": bases(texto),
        "digest_pinado": digest_pinado_na_base_final(texto),
        "base_minima": base_minima(texto),
        "expoe_segredo": expoe_segredo(texto),
    }
    vereditos["aprovada"] = bool(
        vereditos["nao_root"]
        and vereditos["digest_pinado"]
        and vereditos["base_minima"]
        and not vereditos["expoe_segredo"]
    )
    return vereditos

Referência executável 2 — lab/drenagem_grace.py. Registra handlers de SIGTERM/SIGINT, drena o tráfego (fecha a entrada antes de tocar no trabalho em curso), conclui ou cancela dentro do prazo e publica a timeline com o exit code (oráculo LT03-AT-002). Só stdlib (asyncio, signal, time); handlers com semântica POSIX:

"""Drenagem e grace: fechar a entrada, concluir ou cancelar, sair no prazo.

Referencia executavel do Bloco 1.
Implementacao verbatim na folha B01-L. So STDLIB (asyncio, signal, time).
Ponte com o LT01-B01: mesmo shutdown cooperativo, com a drenagem a frente.
"""

from __future__ import annotations

import asyncio
import signal
import time
from collections.abc import Callable

CODIGO_SAIDA_LIMPA = 0


class ServicoDrenavel:
    """Guarda o estado da drenagem: entrada aberta ou fechada."""

    def __init__(self) -> None:
        self.aceitando = True
        self.concluidas = 0
        self.canceladas = 0

    def fechar_entrada(self) -> None:
        """Passo 1: nenhum trafego novo depois do sinal."""
        self.aceitando = False

    async def atender(self, duracao: float) -> str:
        """Trabalho cooperativo: responde a cancelamento."""
        if not self.aceitando:
            raise RuntimeError("entrada fechada: trafego novo recusado")
        try:
            await asyncio.sleep(duracao)
        except asyncio.CancelledError:
            self.canceladas += 1
            raise
        self.concluidas += 1
        return "concluida"


async def drenar(
    servico: ServicoDrenavel,
    em_curso: set[asyncio.Task[object]],
    prazo: float,
) -> dict[str, float]:
    """Fecha a entrada, aguarda ate o prazo, cancela o restante, publica a timeline."""
    inicio = time.monotonic()
    servico.fechar_entrada()
    _, pendentes = await asyncio.wait(em_curso, timeout=prazo)
    for tarefa in pendentes:
        tarefa.cancel()
    await asyncio.gather(*pendentes, return_exceptions=True)
    return {
        "concluidas": float(servico.concluidas),
        "canceladas": float(servico.canceladas),
        "relógio_s": time.monotonic() - inicio,
        "codigo_saida": float(CODIGO_SAIDA_LIMPA),
    }


def instalar_handlers(
    loop: asyncio.AbstractEventLoop,
    ao_sinal: Callable[[], None],
) -> None:
    """SIGTERM e SIGINT pedem drenagem; SIGKILL nao passa por aqui."""
    for numero in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(numero, ao_sinal)

  • Imagem OCI é empacotamento padronizado: camadas empilhadas, config de execução, manifest que lista, digest que identifica.
  • Tag é apelido mutável; promoção e rollback referenciam o digest imutável, nunca o nome legível.
  • Imagem Python séria é mínima, em estágios, com dependências bloqueadas, non-root, versionada e sem segredo em camada alguma.
  • No container, o SIGTERM chega ao PID 1: drenar o tráfego primeiro, concluir ou cancelar no grace e sair com o exit code contratado.

N1 · API declarativa: pedir estado, reconciliar realidade

API declarativa é a interface onde você descreve o estado desejado e o sistema trabalha até a realidade coincidir com ele. O desired state é o documento versionado: quantas réplicas, qual imagem por digest, quais portas, quais montagens. O observed state é o que existe de fato: Pods rodando, endpoints publicados, conditions registradas. Entre os dois opera o control loop: observar, comparar, agir, repetir. Aplicar o manifesto não executa uma sequência; registra uma intenção que controladores perseguem continuamente (oráculo AT-010: o estado observado converge ao manifesto).

N2 · Workloads pelo ciclo de vida, rede e configuração

O erro de entrada é tratar todo workload como réplica genérica. Cada controlador promete um ciclo de vida distinto; a escolha começa pela pergunta sobre término, identidade e lugar:

WorkloadCaso que resolveLimite que decide
DeploymentAPI sem estado com réplicas intercambiáveis: troca versão por rollout, repõe falha, escala por número. É o workload da API desta trilha.Réplicas são gêmeas: qualquer dado que precise sobreviver ao Pod não mora aqui (ponte com AT-014).
StatefulSetRéplicas com identidade estável — nome ordinal, rede estável, storage próprio por réplica — para estado que acompanha o membro.Identidade cobra ordem e lentidão de escala; usar para API sem estado é pagar coordenação sem receber nada.
DaemonSetUm agente por nó elegível: coleta, proxy local, varredura. Nasce com o nó, morre com o nó.Um por nó é multiplicação automática de custo; fora de agente de nó, é réplica sem motivo.
JobTarefa que termina: migração, lote, verificação. Sucesso é conclusão contada, não presença contínua.Job que nunca termina é serviço disfarçado; serviço que deveria terminar e fica preso é Job sem deadline nem backoff pensado.
CronJobJob sob agenda: cada horário cria um Job filho com o mesmo contrato de conclusão.Agenda não é fila: sobreposição de execuções exige política de concorrência e histórico limitado, ou o cluster acumula filhos.

Rede: expor só a API. O Service é o nome estável diante de Pods instáveis: seleciona por selector, publica endpoints e oferece DNS interno pelo nome. O worker desta trilha não recebe Service externo: é alcançado pela fila, não pela rede. Gateway ou Ingress é a porta de entrada do cluster: recebe tráfego externo e roteia ao Service interno por regra declarada. A cadeia de seleção é única — regra aponta ao Service, Service seleciona Pods por selector, endpoints publicam quem está pronto — e cada elo quebrado tem sintoma próprio no diagnóstico.

Configuração: ConfigMap contra Secret. ConfigMap carrega dado não sensível: flags, nomes, timeouts legíveis. Secret carrega referência sensível — e referência não é cofre: o conteúdo viaja em base legível por quem lê o objeto, mora no estado e aparece em evidência descuidada. Por isso este bloco congela a regra que o validador cobra: nenhum segredo literal em variável de ambiente de manifesto; segredo chega por referência montada na execução, nunca copiado no documento versionado. Config ausente ou chave trocada é falha catalogada: o Pod nasce e morre pedindo o que ninguém entregou.

Persistência: efêmero contra durável. O filesystem do container é efêmero: reinício limpa, recriação apaga, escala espalha. Volume é o disco declarado fora do ciclo do container; persistência real é o volume cuja vida supera o Pod — com classe, reclaim e backup pensados. O oráculo AT-014 cobra a distinção: dado que precisa sobreviver não reside apenas no container, e reinício nunca é confundido com leitura de durabilidade.

Identidade e permissão: ServiceAccount com RBAC mínimo. Todo Pod fala com a API do cluster sob uma ServiceAccount; o RBAC diz quais verbos sobre quais recursos em qual escopo essa conta pode executar. Mínimo significa exatamente o necessário: a conta da API não carrega os verbos do worker, e o worker não carrega credencial nem permissão da API (aceitação do bloco e AT-012). Security context declara usuário, grupo, filesystem read-only e capacidades descartadas; os Pod Security Standards convertem essas declarações em patamares exigíveis por namespace. Conta ampla é defeito silencioso: tudo funciona até o dia em que funciona demais.

Contraste"Apliquei, então está isolado e autorizado" — não. Aplicar registra intenção; isolamento e autorização vêm de objetos próprios que precisam existir e casar: NetworkPolicy que seleciona os Pods certos, RBAC preso à conta certa, selector que encontra label real. O sintoma que denuncia a ilusão é conhecido: o manifesto aplica limpo, o tráfego atravessa onde não deveria, a conta alcança o que nunca usa, e o diagnóstico começa pelo objeto que ninguém escreveu. Os oráculos AT-011..014 cobram os quatro vínculos: endpoints publicados, verbos mínimos, testes de rede positivos e negativos, dado fora do container.

Rede como política: default-deny e allowlist. NetworkPolicy filtra tráfego entre Pods nas camadas de endereço e porta: por padrão, tudo passa; com default-deny no namespace, nada passa exceto o declarado na allowlist. A regra honesta desta trilha nega tudo e libera o estrito: API recebe da porta de entrada, worker fala com fila e banco, banco só ouve o worker — e DNS precisa constar, porque negar o nome derruba tudo antes de qualquer teste de aplicação. E o limite arquitetural: a política só vale onde o CNI a implementa; em plugin que ignora a API, manifesto correto é carta sem carteiro (AT-013 registra a dependência).

N3 · Probes, recursos e escala: a semântica que o manifesto contrata

Probe é a pergunta periódica que o runtime faz ao container, e cada tipo produz somente a reação pretendida — uma nunca substitui a outra (regra da especificação):

ProbePergunta e reação contratadaDefeito catalogado
Startup"Terminaste de inicializar?" Enquanto falha, as demais ficam suspensas: protege subida lenta contra veredito precoce.Ausente em inicialização longa, as outras probes condenam um processo que ainda estava nascendo.
Readiness"Aceitas tráfego?" Falha remove o Pod dos endpoints sem matar o processo: controla tráfego, nunca reinicia.Readiness que chama dependência externa tira do ar quem está saudável por culpa do vizinho; confundir com liveness cria restart loop onde bastava drenar tráfego.
Liveness"Estás vivo ou travado?" Falha reinicia o container: o último recurso contra deadlock interno.Liveness que consulta banco, fila ou DNS converte lentidão alheia em suicídio próprio — o defeito mais caro deste bloco.

Recursos: pedir para agendar, limitar para conter. Request é a reserva que o agendador usa para escolher o nó: sem request medido, o Pod cabe em qualquer lugar e em lugar nenhum com garantia. Limit é o teto imposto na execução: CPU além do limite é estrangulada (throttle), memória além do limite mata o container (OOMKill). Valores sem medição são hipótese — a regra da especificação — e a prova pertence ao Bloco 3; aqui o contrato exige presença declarada e coerência: request sustenta o agendamento, limit contém o dano, e a combinação dos dois define a QoS (qualidade de serviço): garantida quando pedido e teto coincidem por container, intermediária quando só parte garante, oportunista quando nada é declarado. Limite arbitrário copiado de outro serviço é hipótese vestida de decisão.

HPA com limites honestos. O HPA é um control loop atrasado: lê métrica, compara com o alvo, ajusta réplicas, espera o efeito — e cada passo leva tempo de imagem, inicialização e aquecimento. Depende de requests declarados para calcular utilização; sem request, a porcentagem-alvo não tem denominador. Não cria capacidade instantânea, oscila sem estabilização e jamais corrige dependência saturada: escalar a API contra banco esgotado multiplica a pressão sobre o gargalo (ponte com o AT de upstream do Bloco 3). Números de réplicas, alvos e janelas citados neste bloco são exemplo variável; a curva carga contra réplicas com SLO preservado é medida no Bloco 3.

Fundamento de engenharia · Declarar é contratar reação. Cada campo do manifesto contrata uma reação do sistema: selector contrata endpoints, probe contrata tráfego ou reinício, request contrata agendamento, limit contrata contenção, política contrata bloqueio. Manifesto incompleto não é manifesto simples — é contrato em branco que o cluster preenche com padrão silencioso. O validador da folha B02-L existe por isso: recusa o branco antes que o silêncio vire incidente.

"""Validacao estatica de manifestos declarativos: probes, recursos, segredo.

Referencia executavel do Bloco 2.
Implementacao verbatim na folha B02-L. So STDLIB (re).
Manifestos entram como dicts Python puros; sem PyYAML, sem rede, sem cluster.
"""

from __future__ import annotations

import re

PADRAO_SECRETO = re.compile(r"(senha|secret|token|password|passwd|pwd|api[_-]?key)", re.IGNORECASE)


def conteineres(manifesto: dict[str, object]) -> list[dict[str, object]]:
    """Extrai a lista de containers do manifesto, ou lista vazia."""
    especificacao = manifesto.get("especificacao")
    if not isinstance(especificacao, dict):
        return []
    lista = especificacao.get("conteineres")
    if not isinstance(lista, list):
        return []
    return [item for item in lista if isinstance(item, dict)]


def probes_presentes(container: dict[str, object]) -> dict[str, bool]:
    """True por probe presente: inicializacao, prontidao, vivacidade."""
    sondas = container.get("sondas")
    nomes: set[str] = set()
    if isinstance(sondas, dict):
        for chave in sondas:
            nomes.add(str(chave))
    return {
        "inicializacao": "inicializacao" in nomes,
        "prontidao": "prontidao" in nomes,
        "vivacidade": "vivacidade" in nomes,
    }


def recursos_declarados(container: dict[str, object]) -> bool:
    """True quando pedido e teto existem para CPU e memoria."""
    recursos = container.get("recursos")
    if not isinstance(recursos, dict):
        return False
    pedido = recursos.get("pedido")
    teto = recursos.get("teto")
    if not isinstance(pedido, dict) or not isinstance(teto, dict):
        return False
    tem_pedido = pedido.get("cpu") and pedido.get("memoria")
    tem_teto = teto.get("cpu") and teto.get("memoria")
    return bool(tem_pedido and tem_teto)


def expoe_segredo_em_env(container: dict[str, object]) -> bool:
    """True se alguma variavel de ambiente carrega nome ou valor de segredo."""
    ambiente = container.get("env")
    if not isinstance(ambiente, list):
        return False
    for entrada in ambiente:
        if not isinstance(entrada, dict):
            continue
        nome = str(entrada.get("nome", ""))
        valor = str(entrada.get("valor", ""))
        if PADRAO_SECRETO.search(nome) or PADRAO_SECRETO.search(valor):
            return True
        if "segredo_literal" in entrada:
            return True
    return False


def seletor_encontra_labels(seletor: dict[str, str], labels: dict[str, str]) -> bool:
    """True quando todo par do seletor existe identico nas labels."""
    for chave, valor in seletor.items():
        if labels.get(chave) != valor:
            return False
    return bool(seletor)


def relatorio(manifestos: list[dict[str, object]]) -> dict[str, object]:
    """Junta as verificacoes; 'aprovado' exige todas as condicoes."""
    violacoes: list[str] = []
    for manifesto in manifestos:
        nome = str(manifesto.get("nome", "sem-nome"))
        for container in conteineres(manifesto):
            sondas = probes_presentes(container)
            if not (sondas["prontidao"] and sondas["vivacidade"]):
                violacoes.append(nome + ": probe obrigatoria ausente")
            if not recursos_declarados(container):
                violacoes.append(nome + ": recursos nao declarados")
            if expoe_segredo_em_env(container):
                violacoes.append(nome + ": segredo em env")
    veredito: dict[str, object] = {"violacoes": violacoes}
    veredito["aprovado"] = not violacoes
    return veredito

from __future__ import annotations


def passo(
    prontas_total: int,
    removidas: int,
    desejadas: int,
    max_indisponiveis: int,
) -> dict[str, int]:
    """Quantas replicas antigas podem sair neste passo logico.

    Cada nova pronta libera uma remocao; max_indisponiveis autoriza
    a margem inicial. Sem nenhuma pronta, nada sai: a trava de
    readiness e absoluta.
    """
    if not prontas_total >= 1:
        return {"prontas_total": prontas_total, "removiveis": 0}
    margem = prontas_total - removidas + max_indisponiveis
    if not margem >= 1:
        return {"prontas_total": prontas_total, "removiveis": 0}
    restantes = desejadas - removidas
    if not restantes >= 1:
        return {"prontas_total": prontas_total, "removiveis": 0}
    return {"prontas_total": prontas_total, "removiveis": min(margem, restantes)}


def simular(
    desejadas: int,
    sequencia_prontidao: list[bool],
    max_indisponiveis: int,
) -> dict[str, object]:
    """Avanca a troca versao antiga contra nova; aborta se a nova nao fica pronta."""
    prontas_total = 0
    removidas = 0
    linha: list[str] = []
    for sinal in sequencia_prontidao:
        if sinal:
            prontas_total += 1
        veredito = passo(prontas_total, removidas, desejadas, max_indisponiveis)
        removidas += veredito["removiveis"]
        linha.append("prontas=" + str(prontas_total) + ",removidas=" + str(removidas))
        if removidas >= desejadas:
            break
    veredito_final: dict[str, object] = {"linha": linha, "removidas": removidas}
    veredito_final["concluiu"] = removidas >= desejadas
    return veredito_final

N1 · Probes: a pergunta certa com a reação certa

Probe é a pergunta periódica do runtime ao container — e cada tipo contrata exatamente uma reação (regra 4 da especificação). Startup ("terminaste de inicializar?") suspende as demais enquanto falha: protege subida lenta contra veredito precoce. Readiness ("aceitas tráfego?") remove o Pod dos endpoints sem matar o processo. Liveness ("estás vivo ou travado?") reinicia o container: último recurso contra deadlock interno.

Dois defeitos catalogados decidem o AT-020: liveness que consulta dependência externa converte lentidão alheia em suicídio próprio — o mais caro deste bloco; readiness que chama dependência crítica tira do ar quem está saudável por culpa do vizinho. Dependência externa pertence à readiness, nunca ao reinício; e probe que custa mais que o handler é monitoramento que virou carga.

preStop, grace e draining. O preStop é o gancho executado antes do SIGTERM: avisa a dependência, fecha a entrada, inicia a drenagem. O grace period é o prazo contratado entre SIGTERM e SIGKILL (ponte B01-L). Draining é retirar os endpoints antes de tocar no trabalho: nenhuma requisição nova após o sinal; in-flight conclui ou cancela no prazo (AT-023). Pod que termina sem request truncado é pod que drenou primeiro.

N2 · Recursos: pedir para agendar, limitar para conter

Request é a reserva que o agendador usa para escolher o nó; limit é o teto imposto na execução via cgroups. CPU além do limite é throttling — estrangulamento que alonga a cauda sem matar; memória além do limite é OOMKill — morte do container. Ephemeral storage segue a mesma lógica, com despejo em vez de morte elegante. Valores sem medição são hipótese (regra 5): o pedido nasce da medição do steady state mais margem, nunca de outro serviço.

A combinação define a QoS: garantida quando pedido e teto coincidem (última a sofrer sob pressão), intermediária quando só parte é garantida, oportunista quando nada é declarado (primeira a morrer). Limite arbitrário copiado é hipótese vestida de decisão — e request ausente é pior: sem pedido, o HPA perde o denominador da porcentagem-alvo.

N3 · Scheduling, disrupção e o loop atrasado do HPA

Scheduling escolhe o nó por recursos, afinidade e restrições: affinity e spread espalham réplicas entre nós e zonas; taints repelem o que não foi tolerado. Réplicas que cabem num nó só não são alta disponibilidade. PDB limita disrupções voluntárias — drain, upgrade — ao mínimo contratado. O limite honesto: PDB não protege contra crash, delete direto ou falta de capacidade (regra 6).

O HPA é um control loop atrasado: lê a métrica, compara ao alvo, ajusta réplicas, espera imagem, inicialização e aquecimento. A regra é teto de atuais vezes métrica sobre alvo, presa entre capacidade mínima e máxima: dentro da faixa, sem thrash; fora, presa ao contrato. Não cria capacidade instantânea, oscila sem estabilização — e jamais corrige dependência saturada: escalar contra upstream esgotado multiplica a pressão sobre o gargalo, então a escala é negada (AT-025). Capacidade mínima, queue age e cold start entram no desenho; scale-to-zero é trade-off: custo zero parado contra primeira requisição fria.

N4 · Falha e diagnóstico: o catálogo da capacidade

Cada falha abaixo tem oráculo nomeado na folha B03-L: função que reproduz, veredito calculado e conserto que fecha o vínculo. O drain que encontra PDB impossível é negado antes da mutação; a escala que amplificaria o gargalo sequer é emitida.

from __future__ import annotations

import math

REACOES: dict[str, str] = {
    "inicializacao": "suspende-as-demais",
    "prontidao": "remove-dos-endpoints",
    "vivacidade": "reinicia-container",
}


def reacao(tipo: str) -> str:
    """Reacao contratada de cada probe; tipo desconhecido e defeito."""
    return REACOES.get(tipo, "tipo-desconhecido")


def vivacidade_segura(usa_dependencia_externa: bool) -> bool:
    """Liveness so observa estado interno; externa converte lentidao em suicidio."""
    return not usa_dependencia_externa


def classificar_qos(pedido: dict[str, bool], teto: dict[str, bool]) -> str:
    """Garantida (pedido==teto), intermediaria (pedido parcial), oportunista (nada)."""
    chaves = ("cpu", "memoria")
    iguais = sum(1 for c in chaves if pedido.get(c) and teto.get(c))
    pedidos = sum(1 for c in chaves if pedido.get(c))
    if iguais == 2:
        return "garantida"
    if pedidos >= 1:
        return "intermediaria"
    return "oportunista"


def pedido_por_medicao(medicao: float, margem: float) -> float:
    """Request recalculado por medida, nunca copiado de outro servico (AT-021)."""
    return medicao * (1.0 + margem)


def replicas_desejadas(atuais: int, metrica: float, alvo: float) -> int:
    """Regra do HPA: teto de atuais*(metrica/alvo); sem request nao ha denominador."""
    if atuais < 1 or alvo <= 0.0:
        return 1
    return max(1, math.ceil(atuais * metrica / alvo))


def estabilizar(desejadas: int, minimo: int, maximo: int) -> int:
    """Prende a saida do loop na capacidade contratada: sem thrash fora da faixa."""
    return min(max(desejadas, minimo), maximo)


def disrupcao_permitida(replicas: int, removendo: int, minimo_pdb: int) -> bool:
    """PDB limita disrupcao voluntaria: sobra apos remocao respeita o minimo."""
    return replicas - removendo >= minimo_pdb


def espalhadas_ok(distribuicao: list[int]) -> bool:
    """Mais de uma replica no mesmo no nao e alta disponibilidade (AT-022)."""
    total = sum(distribuicao)
    if total <= 1:
        return True
    ocupados = sum(1 for n in distribuicao if n >= 1)
    return ocupados >= 2


def concluir_no_prazo(duracoes: list[float], prazo: float) -> dict[str, int]:
    """Shutdown sob carga sem relogio: conclui o que cabe, cancela o resto."""
    concluidas = sum(1 for d in duracoes if d <= prazo)
    return {"concluidas": concluidas, "canceladas": len(duracoes) - concluidas}


def escala_permitida(upstream_saturado: bool) -> bool:
    """Upstream saturado nega escala: autoscaling nao amplifica o gargalo."""
    return not upstream_saturado

N1 · Declarativo contra procedural: o plano antes da mutação

IaC declarativa registra o estado final desejado da infraestrutura; o motor calcula o caminho. Procedural registra os passos; repetir é rezar pela mesma ordem no mesmo mundo. A diferença decide o oráculo AT-030: após um apply, o segundo plan não contém mudança inesperada — converge para zero. Plan não é prova de segurança nem disponibilidade (regra 8): é a proposta legível antes da mutação, onde mudança destrutiva é lida, não descoberta.

O resource graph é o mapa de dependências entre recursos: quem precede quem, o que cai junto. Provider é o adapter que traduz intenção em chamadas; módulo é o pacote reutilizável com input e output explícitos; dependency lock congela provider em versão exata. Provider flutuante é rebuild sorteado na infraestrutura — o mesmo defeito da base sem digest do Bloco 1, um nível acima.

N2 · State, drift, import e move: a memória que decide

O state é a memória do último apply: que endereços existem, com que valores. Sem ele, todo plan é palpite; com ele corrompido ou concorrido, dois applies disputam o mesmo mundo — por isso backend remoto com locking: um escritor por vez, histórico protegido. E state é dado sensível: carrega valores reais, às vezes segredos — acesso mínimo, nunca em log ou evidência (AT-033).

Drift é a diferença entre o arquivado e o real: alguém mexeu fora da IaC. Detectar é listar; decidir é registrar — reverter pela IaC ou adotar intencionalmente. Import adota o preexistente sob um endereço sem recriar; move reendereça sem recriar (AT-032). Rename que força replace é o defeito catalogado: o endereço novo nasce, o antigo morre, o dado junto se ninguém pensou. Separação de ambientes e blast radius fecham a seção: cada ambiente com state próprio, cada mudança com raio conhecido — e target fora do sandbox é recusado antes da ação (AT-034).

N3 · Lifecycle seguro e segredos: o que nunca entra no documento

Lifecycle seguro é a disciplina dos quatro verbos: plan revisável salvo, apply intencional, refresh que atualiza a leitura sem culpar o documento, destroy guardado por nome e contexto absolutos do sandbox. Scripts validam contexto, nome e diretório antes de destroy; restore idempotente; nenhuma ação alcança outros clusters ou recursos do host.

Segredos e credenciais curtas: segredo nunca mora em state legível, output, variável literal ou evidência — chega por referência, com vida curta, no momento da execução. Policy e checks convertem regra em barreira automática: o proibido falha antes da mutação, não no postmortem. Target usado como rotina é defeito catalogado: atalho de hoje é incidente de escopo de amanhã.

from __future__ import annotations

import re

PADRAO_SECRETO = re.compile(r"(senha|secret|token|password|api[_-]?key)", re.IGNORECASE)
SANDBOX_AUTORIZADO = "course-lt03"


def plano(desejado: dict[str, str], observado: dict[str, str]) -> dict[str, list[str]]:
    """Diff declarado contra observado: criar, atualizar, destruir por endereco."""
    criar = sorted(e for e in desejado if e not in observado)
    destruir = sorted(e for e in observado if e not in desejado)
    atualizar = sorted(e for e in desejado if e in observado and desejado[e] != observado[e])
    return {"criar": criar, "atualizar": atualizar, "destruir": destruir}


def vazio(resultado: dict[str, list[str]]) -> bool:
    """Plano vazio converge: segundo plan apos apply nao contem mudanca."""
    return not resultado["criar"] and not resultado["atualizar"] and not resultado["destruir"]


def aplicar(desejado: dict[str, str], observado: dict[str, str]) -> dict[str, str]:
    """Apply intencional: observado passa a igualar o desejado versionado."""
    novo = dict(observado)
    mudancas = plano(desejado, observado)
    for endereco in mudancas["destruir"]:
        del novo[endereco]
    novo.update(desejado)
    return novo


def detectar_drift(estado_arquivo: dict[str, str], real: dict[str, str]) -> list[str]:
    """Enderecos cujo real divergiu do estado arquivado, em ordem."""
    return sorted(e for e in estado_arquivo if real.get(e) != estado_arquivo[e])


def importar(estado: dict[str, str], endereco: str, id_externo: str) -> dict[str, str]:
    """Adota recurso preexistente sem recriar: registra o id sob o endereco."""
    novo = dict(estado)
    novo[endereco] = id_externo
    return novo


def mover(estado: dict[str, str], origem: str, destino: str) -> dict[str, str]:
    """Reendereca sem recriar: mesmo valor, nova chave, origem removida."""
    novo = dict(estado)
    novo[destino] = novo.pop(origem)
    return novo


def contem_segredo(objeto: dict[str, str]) -> bool:
    """True se chave ou valor carrega segredo: state e dado sensivel (AT-033)."""
    for chave, valor in objeto.items():
        if PADRAO_SECRETO.search(chave) or PADRAO_SECRETO.search(valor):
            return True
    return False

    """Destroy so no sandbox autorizado: resto recusado antes da acao (AT-034)."""
    return alvo == sandbox

N1 · OpenGitOps: o Git como fonte da verdade puxada

GitOps é operar pelo Git como única fonte da verdade, com quatro princípios (regra 9 da especificação): estado declarativo (o quê, não o como), versionado e imutável (histórico que não se reescreve), puxado (o cluster busca; nada empurra de fora para dentro) e continuamente reconciliado (o controlador persegue o declarado sem parar). CI que faz push no cluster não satisfaz sozinho esses princípios: empurra sem reconciliar, e o que não é reconciliado diverge em silêncio.

A separação que sustenta tudo: source é o código versionado; build artifact é a imagem imutável identificada por digest (Bloco 1); environment config é o que varia por ambiente — réplicas, endpoints, flags. Promoção move o mesmo digest entre ambientes, trocando só a config (AT-043). Branch contra diretório contra repositório é decisão de ownership: cada escolha diz quem aprova o quê, e duas automações editando o mesmo campo é o defeito catalogado da briga de controladores.

N2 · Reconciliação, drift e break-glass: o loop que não perdoa manual

Reconciliação é o control loop do GitOps: ler o declarado no Git, comparar ao observado, convergir, registrar revisão e digest no status (AT-040). Mudança sem commit não persiste: o drift manual — patch à mão no cluster — é revertido pelo reconciler, e o evento entra na trilha de auditoria (AT-041).

A exceção é o break-glass: quebrar o vidro em incidente, com motivo registrado, escopo mínimo e TTL que expira — passado o prazo, a reversão volta a valer. Vidro quebrado sem motivo, sem prazo ou sem reversão posterior é edição manual com outro nome. Config inválida falha de modo visível sem apagar o último saudável quando assim configurado (AT-042): commit ruim é commit visível, nunca sumiço silencioso do que funcionava.

N3 · Promoção e segredos: identidade que atravessa, segredo que não versiona

Promoção por digest é a prova de identidade da trilha inteira: dev, homolog e prod rodam o mesmo conteúdo exato, citado pelo hash, com diff revisável antes de cada passo. Overlays sem copy/paste aplicam a diferença por ambiente sobre a base comum — mesma base, patches declarados, nada duplicado para divergir.

Segredos criptografados ou externos: guardar secret em Git é fora de escopo desta trilha — segredo versionado é segredo publicado. O declarado no Git é referência (onde buscar, com que permissão); o valor chega na execução por cofre ou controlador externo. Ownership fecha a seção: cada campo tem um dono automatizado, e campo sem dono é campo em disputa.

N4 · Falha e diagnóstico: o catálogo da reconciliação

Cada falha abaixo tem oráculo nomeado na folha B05-L: dado que reproduz, veredito calculado e conserto que restaura a fonte da verdade. Comando manual de incidente vira commit, expira ou é revertido — nunca permanece como sombra.

Bloco 6 · Progressive delivery, rollback e incidente de plataforma

Orientação: o que este bloco entrega

OrientaçãoO que será aprendido. Este bloco troca deploy total por promoção graduada com decisão por dados: nove resultados (LT03-B06-C01..09; matriz PLAT-03, SRE-01, SRE-02, SEN-01):

  • separar rolling, blue/green e canary pelo que cada estratégia expõe e preserva;
  • desenhar análise por erro, latência e métrica de negócio, com janela, threshold e veredito inconclusivo que nunca vira sucesso (LT03-AT-050/051/052);
  • abortar automaticamente a regressiva antes de 100% com o stable preservado no SLO;
  • decidir rollback contra roll-forward sabendo que workload não reverte schema, dado ou efeito externo (LT03-AT-053);
  • diagnosticar por camada — aplicação, manifesto, controlador, nó, rede, dependência — e restaurar reconciliação e lab (LT03-AT-060/061);
  • ler a referência executável — lab/analisar_canary.py — sem exigir tráfego real. A execução pertence à folha B06-L, no Laboratório guiado LT03.

Pré-requisitos. Blocos 2 a 5 (rollout travado, plano convergido, reconciliação, digest como identidade) e M12 (SLO). Cada termo novo — canary, threshold, roll-forward, expand/migrate/contract — é definido no ponto de uso. Todo exemplo é Python 3.14 com só stdlib. Nenhuma outra stack é pressuposta.

Saída observável. Ao fim da leitura, você desenha etapas com análise, aborta por threshold, bloqueia rollback incompatível e localiza incidente por camada — e lê o contrato do lab/ sem precisar executá-lo aqui.

N1 · Estratégias: o que cada entrega expõe

Rolling troca réplicas aos poucos sob a trava de readiness (folha B02-L): barato, sem duplicar capacidade, mas mistura versões durante a janela. Blue/green sobe o ambiente novo inteiro ao lado, vira o tráfego de uma vez e mantém o antigo para volta rápida: dobra custo temporário em troca de corte limpo. Canary expõe a nova versão a percentuais graduais com análise entre etapas: representatividade crescente com blast radius contido.

Segmentação e representatividade: canary só prova o que o tráfego segmentado representa — percentual irrisório ou público enviesado é teatro de análise. Pause e approval seguram a promoção para decisão humana; auto-promotion e abort movem sozinhos pelo veredito calculado. Versão ruim não alcança 100%: a trava é o threshold, não a esperança.

N2 · Análise: erro, latência e o inconclusivo que cala

Análise compara stable contra canary em janela fixa: taxa de erro, p95 e métrica de negócio, cada uma com threshold declarado. Canary além do threshold aborta; dentro, promove; sem amostra mínima, o veredito é inconclusivo — e inconclusivo nunca é convertido silenciosamente em sucesso (AT-052). Métricas calculadas de tráfego real do lab, nunca hardcoded: número sem tráfego é cenário, não evidência.

Rollback contra roll-forward: rollback de aplicação não reverte automaticamente schema, mensagem, dado ou efeito externo (regra 10). Com migração no caminho, a volta exige compatibilidade expand/migrate/contract provada nas duas direções — ou o rollback é bloqueado e o caminho é seguir adiante (AT-053). Feature flags separam deploy de exposição: código novo parado, comportamento novo aceso por chave — rollback vira desligar, sem novo deploy.

N3 · Incidente: localizar por camada, restaurar por contrato

Diagnóstico por camada diante do inédito: eventos e conditions primeiro, depois logs, métricas e traces — aplicação, manifesto, controlador, nó, rede, dependência, nesta ordem, até o sinal acender (AT-060). Cada camada tem sintoma próprio; pular ordem é trocar investigação por adivinhação.

Restauração fecha o ciclo: SLO de volta, Git representando o desejado, controladores saudáveis, faults desligados, recursos de sandbox removíveis (AT-061). Postmortem registra timeline, decisão e compatibilidade — incidente sem registro é ensaio para repetição.

N4 · Falha e diagnóstico: o catálogo da entrega

Cada falha abaixo tem oráculo nomeado na folha B06-L: métrica que reproduz, veredito calculado e conserto que fecha o vínculo. A decisão deriva de dados calculados; rollback nunca corrompe contrato.

"""Canary como dados: analise por metrica, abort/promocao e rollback, sem trafego.

Referencia executavel do Bloco 6.
Implementacao verbatim na folha B06-L. So STDLIB.
Oraculos LT03-AT-050..053, 060, 061 sobre dicts puros e aritmetica local.
"""

from __future__ import annotations


def analisar(
    erro_stable: float,
    erro_canary: float,
    p95_stable: float,
    p95_canary: float,
    limiar_erro: float,
    limiar_p95: float,
    amostras: int,
    minimo_amostras: int,
) -> str:
    """Promove, aborta ou declara inconclusiva; inconclusiva nunca vira sucesso."""
    if amostras < minimo_amostras:
        return "inconclusiva"
    if erro_canary > erro_stable + limiar_erro or p95_canary > p95_stable + limiar_p95:
        return "abortar"
    return "promover"


def rollback_compativel(novo_le_antigo: bool, antigo_le_novo: bool) -> bool:
    """Rollback de workload nao reverte schema: exige leitura cruzada provada."""
    return novo_le_antigo and antigo_le_novo


def localizar_camada(sinais: dict[str, bool]) -> str:
    """Primeira camada com sinal aceso, na ordem aplicacao a dependencia."""
    for camada in ("aplicacao", "manifesto", "controlador", "no", "rede", "dependencia"):
        if sinais.get(camada):
            return camada
    return "indeterminada"


def restaurar(falhas_ativas: list[str]) -> dict[str, object]:
    """Lab restaurado: sem falhas, reconciliacao ligada, sandbox removivel."""
    return {
        "falhas_ativas": [f for f in falhas_ativas if f],
        "reconciliacao": not falhas_ativas,
        "removivel": not falhas_ativas,
    }
