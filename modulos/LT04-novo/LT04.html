Trilha LT04 · Tier 1 6 blocos / recorte release · Pré-requisitos: M03, LT01–LT03
Do número solto à decisão reproduzível: versionar, barrar, reverter, medir, comunicar e aprender.

O que muda ao final deste recorte. Até aqui você publicou código que funciona: o M03 deu a API, o LT01 deu o runtime observado, o LT03 deu o rollout. Mas houve um momento em que a explicação parou em "subimos a latest", "o gate passou e quebrou mesmo assim" ou "voltamos e ficou pior": por que a tag que rodou ontem não identifica mais nada hoje, por que um gate sem evidência aprovou um release ruim, por que o rollback restaurou o binário e perdeu o dado, por que a média verde escondeu a cauda vermelha, por que ninguém sabia quem podia dizer não, por que o incidente se repetiu sem dono. Este recorte leva o release Python da versão ao aprendizado — número ordenado, barreira com evidência, reversão verificada, sinal que não mente, decisão comunicável, incidente com dono — e para exatamente aí: sem formar auditor de supply chain, sem assinar artefato real, sem operar cluster. Ao final você terá vinculado versão a digest imutável, emitido GO/CONDITIONAL/NO-GO por cálculo e revertido por stop condition com restauração verificada. Núcleo validável no lab/ com só stdlib; onde release, deploy real, cloud ou GPU forem exigidos, os oráculos nascem BLOCKED com registro, nunca com simulação.

Bloco 1 · Versionamento e changelog

Orientação: o que este bloco entrega

OrientaçãoO que será aprendido. Este bloco troca "subimos a latest" por identidade ordenada e história legível. Três resultados saem daqui (LT04-T1-AT-001..003; ponte com spec B06/Q4):

  • aplicar SemVer estrito como ordem total de release — número que decide precedência, não enfeite (AT-001);
  • exigir changelog com versão, data e resumo em ordem decrescente — decisão legível por humano e máquina (AT-002);
  • vincular versão a digest imutável — tag mutável nunca é identidade do artefato (AT-003, ponte LT04-AT-023);
  • ler a referência executável — lab/versao_release.py — sem exigir registry ou deploy. A execução pertence à folha B01-L, no Laboratório guiado LT04-T1.

Pré-requisitos. Leitura de dicionários e expressões regulares (M02). Cada termo novo — SemVer, changelog, digest — é definido no ponto de uso. Todo exemplo é Python 3.14 com só stdlib. Nenhuma outra stack é pressuposta.

Saída observável. Ao fim da leitura, você recusa latest como identidade, ordena releases e acusa changelog fora de ordem — e lê o contrato do lab/ sem precisar executá-lo aqui.

N1 · SemVer: o número que decide precedência

SemVer escreve a versão como MAJOR.MINOR.PATCH: MAJOR quebra compatibilidade, MINOR adiciona sem quebrar, PATCH corrige. A comparação é numérica por campo, não lexicográfica: 1.10.0 é posterior a 1.9.9, e ordenação de strings diria o contrário. Zeros à esquerda são proibidos (1.02.3 não é versão) e prefixo v não faz parte do número. O oráculo AT-001 exige ordem total: para qualquer par, menor, igual ou maior — sem empate ambíguo.

N2 · Changelog: a história que humano e máquina leem

Changelog é o registro intencional de mudança por versão: cada entrada carrega versão válida, data e resumo do que mudou para quem consome. Entradas em ordem decrescente — a mais nova primeiro — porque leitor de release lê de cima para baixo. Entrada sem data é história sem tempo; sem resumo é número sem decisão. O oráculo AT-002 lista cada problema com posição: campo ausente e quebra de ordem são acusados separadamente, sem máscara mútua.

N3 · Digest: a identidade que a tag não é

Digest (sha256:…) identifica o conteúdo do artefato; tag é apelido mutável que pode apontar para outro conteúdo amanhã. Promover por tag é promover por boato: o oráculo AT-003 só aceita o par versão válida mais digest bem formado, e recusa latest nos dois lados. Assinatura e registry reais pertencem à trilha externa — BLOCKED com registro onde ausentes; aqui o contrato prova o vínculo, não a criptografia.

N4 · Falha e diagnóstico: o catálogo da versão

Cada falha abaixo tem oráculo nomeado na folha B01-L: dado que reproduz, veredito calculado e conserto que fecha o vínculo. Tag mutável como identidade é o defeito raiz: tudo que deriva dela — rollback, auditoria, reprodução — herda a mentira.

"""Versao como contrato: SemVer, changelog ordenado e vinculo com digest.

Referencia executavel do Bloco 1.
Implementacao verbatim na folha B01-L. So STDLIB (re).
Oracalos LT04-T1-AT-001..003; release/deploy real = trilha BLOCKED.
"""

from __future__ import annotations

import re

SEMVER = re.compile(r"^(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)$")


def parse(versao: str) -> tuple[int, int, int]:
    """SemVer estrito X.Y.Z sem zeros a esquerda: devolve (major, minor, patch)."""
    m = SEMVER.match(versao.strip())
    if m is None:
        raise ValueError(f"versao invalida: {versao!r}")
    return (int(m.group(1)), int(m.group(2)), int(m.group(3)))


def comparar(a: str, b: str) -> int:
    """Ordem total de release: -1 se a<b, 0 se igual, +1 se a>b."""
    pa, pb = parse(a), parse(b)
    return (pa > pb) - (pa < pb)


def changelog_valido(entradas: list[dict[str, str]]) -> list[str]:
    """Cada entrada precisa de versao, data e resumo; ordem decrescente."""
    problemas: list[str] = []
    vistas: list[tuple[int, int, int]] = []
    for i, e in enumerate(entradas):
        for campo in ("versao", "data", "resumo"):
            if not e.get(campo, "").strip():
                problemas.append(f"entrada {i}: campo {campo!r} ausente")
        try:
            vistas.append(parse(e.get("versao", "")))
        except ValueError:
            problemas.append(f"entrada {i}: versao invalida")
    for i in range(1, len(vistas)):
        if vistas[i - 1] <= vistas[i]:
            problemas.append(f"entrada {i}: fora de ordem decrescente")
    return problemas


def vincular_digest(versao: str, digest: str) -> dict[str, str]:
    """Liga versao a um digest imutavel: tag mutavel nunca e identidade."""
    parse(versao)
    if not re.fullmatch(r"sha256:[0-9a-f]{64}", digest):
        raise ValueError(f"digest invalido: {digest!r}")
    return {"versao": versao.strip(), "digest": digest}

Bloco 2 · Gates de release

Orientação: o que este bloco entrega

OrientaçãoO que será aprendido. Este bloco troca "o gate passou" por barreira calculada com motivo nomeado. Três resultados saem daqui (LT04-T1-AT-010..012; ponte com spec Q7/P0-P1):

  • avaliar gate como conjunção de evidências: claim sem evidência reprova fechado, sem meio-termo (AT-010, ponte LT04-AT-050);
  • forçar NO-GO com P0/P1 aberto ou gate reprovado — bloqueador não negocia com pressa (AT-011, ponte LT04-AT-051);
  • admitir CONDITIONAL GO só com gate verde mais item com dono, condição e expiração (AT-012, ponte LT04-AT-052);
  • ler a referência executável — lab/gates_release.py — sem exigir assinatura humana. A execução pertence à folha B02-L, no Laboratório guiado LT04-T1.

Pré-requisitos. Bloco 1 (identidade do que se promove) e leitura de dicionários (M02). Cada termo novo — claim, gate, CONDITIONAL GO — é definido no ponto de uso. Todo exemplo é Python 3.14 com só stdlib. Nenhuma outra stack é pressuposta.

Saída observável. Ao fim da leitura, você reprova gate sem evidência, veta release com P0 aberto e escreve condicional com dono e prazo — e lê o contrato do lab/ sem precisar executá-lo aqui.

N1 · Claim e gate: a conjunção que não negocia

Claim é a alegação verificável ("contrato provado", "cauda medida"); gate é a conjunção: aprova somente se toda claim tem evidência presente. Evidência ausente não é "pendência leve": o gate reprova fechado, listando os bloqueadores pelo id. O oráculo AT-010 exige o veredito mais a lista — reprovação sem motivo nomeado é reprovação sem conserto.

N2 · P0/P1: o veto automático

Severidade separa o intolerável do negociável: P0/P1 aberto força NO-GO independente de qualquer outro verde. Não existe "GO com P0 conhecido": conhecer e promover é aceitar o dano por escrito sem o papel. O oráculo AT-011 cobra o motivo com o id do crítico — a decisão carrega o nome do que a vetou. Gate reprovado por qualquer claim sem evidência também veta, mesmo em P2: falha fechada não vira GO por severidade baixa.

N3 · CONDITIONAL GO: o talvez com dono e prazo

CONDITIONAL GO só existe com gate verde mais item condicional completo: dono nomeado, condição verificável e expiração datada. Falta um dos três e o veredito volta a NO-GO — condicional sem dono é dívida com nome bonito, sem prazo é aceitação permanente disfarçada. O oráculo AT-012 testa cada ausência isoladamente: sem dono, sem condição e sem expiração vetam em três casos distintos. GO puro exige gate verde e lista vazia de pendências.

N4 · Falha e diagnóstico: o catálogo da barreira

Cada falha abaixo tem oráculo nomeado na folha B02-L: dado que reproduz, veredito calculado e conserto que fecha o vínculo. Gate que aprova sem evidência é o defeito raiz: toda decisão posterior — rollback, comunicação, pós-mortem — herda a aprovação vazia.

"""Decision engine: GO, CONDITIONAL GO ou NO-GO por calculo declarado.

Referencia executavel do Bloco 2.
Implementacao verbatim na folha B02-L. So STDLIB (sem imports).
Oracalos LT04-T1-AT-010..012; assinatura humana real = trilha BLOCKED.
"""

from __future__ import annotations

BLOQUEANTES = ("p0", "p1")


def avaliar_gate(claims: list[dict[str, object]]) -> dict[str, object]:
    """Gate aprova so com toda evidencia presente: claim sem evidencia falha fechado."""
    bloqueadores = [str(c["id"]) for c in claims if c.get("evidencia") is not True]
    return {
        "veredito": "aprovado" if not bloqueadores else "reprovado",
        "bloqueadores": bloqueadores,
    }


def _invalido(item: dict[str, object]) -> bool:
    """Condicional exige dono, condicao verificavel e expiracao: sem um, nao vale."""
    return (
        not str(item.get("dono", "")).strip()
        or not str(item.get("condicao", "")).strip()
        or not str(item.get("expiracao", "")).strip()
    )


def decidir(
    resultados: dict[str, dict[str, object]],
    claims: list[dict[str, object]],
    condicionais: list[dict[str, object]],
) -> dict[str, object]:
    """NO-GO com P0/P1 aberto ou claim sem evidencia; CONDITIONAL so com gate verde."""
    sem_evidencia = [c for c in claims if c.get("evidencia") is not True]
    criticos = [str(c["id"]) for c in sem_evidencia if c.get("severidade") in BLOQUEANTES]
    reprovados = [n for n, r in resultados.items() if r.get("veredito") != "aprovado"]
    if criticos or reprovados or sem_evidencia:
        motivo = criticos or reprovados or [str(c["id"]) for c in sem_evidencia]
        return {"decisao": "NO-GO", "motivo": motivo}
    invalidos = [str(i.get("item")) for i in condicionais if _invalido(i)]
    if invalidos:
        return {"decisao": "NO-GO", "motivo": invalidos}
    if condicionais:
        return {"decisao": "CONDITIONAL GO", "motivo": [str(i.get("item")) for i in condicionais]}
    return {"decisao": "GO", "motivo": []}

N1 · Stop condition: o abort com nome e número

Stop condition é o limite pré-declarado que aborta a promoção: erro acima de 5%, p99 acima de 800 ms — número, não pressentimento. Declarada antes do rollout, lida durante, obedecida sem reunião: stop que se negocia na hora é enfeite. O oráculo AT-020 devolve a lista de violações em ordem, e lista vazia significa seguir — silêncio calculado, não ausência de leitura.

N2 · Rollback: a volta ao conhecido

Rollback é a promoção reversa ao release anterior conhecido, identificado por digest — não "a versão que funcionava", mas o par versão mais digest registrado no histórico. Sem release anterior não há para onde voltar: o contrato levanta erro explícito em vez de inventar destino. O oráculo AT-021 cobra os dois casos: com stop, rollback ao anterior; sem stop, manter o atual; sem anterior, erro. Roll-forward (corrigir adiante) existe, mas é decisão nova com gate novo — não atalho para fugir do stop.

N3 · Restore: a prova de que voltou

Restauração só existe provada em três eixos: mesmo digest do alvo, dado compatível com o esquema do alvo e serviço saudável. Digest certo com dado incompatível é corrupção restaurada; tudo certo sem saúde é promessa. O oráculo AT-022 testa cada eixo isolado: digest trocado, dado de outro esquema e saúde falsa reprovam em três casos distintos. Evidência de restore entra no dossiê como as demais: digest, verificação e quem atestou.

N4 · Falha e diagnóstico: o catálogo da reversão

Cada falha abaixo tem oráculo nomeado na folha B03-L: dado que reproduz, veredito calculado e conserto que fecha o vínculo. Rollback por tag mutável é o defeito raiz: a volta mira um apelido que pode ter mudado de dono durante a crise.

Referencia executavel do Bloco 3.

from __future__ import annotations


def stop_disparado(metricas: dict[str, float], limites: dict[str, float]) -> list[str]:
    """Condicoes violadas (metrica acima do limite), em ordem; vazio e seguir."""
    return sorted(m for m, teto in limites.items() if metricas.get(m, 0.0) > teto)


def escolher_alvo(historico: list[dict[str, str]], atual: int) -> dict[str, str]:
    """Alvo e o release anterior conhecido: sem anterior, erro explicito."""
    if atual <= 0 or atual >= len(historico):
        raise ValueError(f"sem release anterior para regredir (atual={atual})")
    return historico[atual - 1]


def reverter(
    historico: list[dict[str, str]], atual: int, violacoes: list[str]
) -> dict[str, object]:
    """Com stop disparado, acao e rollback ao digest anterior; sem stop, manter."""
    if not violacoes:
        return {"acao": "manter", "alvo": historico[atual]}
    return {"acao": "rollback", "alvo": escolher_alvo(historico, atual)}


def restauracao_ok(alvo: dict[str, str], estado: dict[str, object]) -> bool:
    """Restore provado: mesmo digest, dado compativel e servico saudavel."""
    return (
        estado.get("digest") == alvo.get("digest")
        and estado.get("dado") == alvo.get("dado")
        and estado.get("saudavel") is True
    )

N1 · Percentis: a cauda tem número

Percentil p é o valor abaixo do qual caem p% das amostras: p99 de 900 ms significa 1% das requisições acima disso — gente real esperando. Nearest-rank ordena as amostras e toma a posição teto(p% de n): cálculo auditável sobre o raw, sem modelo. Média de 54,5 ms com p99 de 900 ms não é "quase 50 ms": é 95% rápido e 5% quebrado. O oráculo AT-030 exige media mais p50/p95/p99 do mesmo raw, com n declarado — número sem amostra não é evidência.

N2 · Dado ausente: o zero que não se inventa

Sinal sem amostra não vale zero: percentil de lista vazia e taxa de erro com total zero levantam erro explícito, nunca retornam 0,0. Zero inventado desarma o stop do Bloco 3: o gate lê "tudo bem" onde deveria ler "sem leitura". O oráculo AT-031 cobra as duas recusas — e o p fora de (0, 100] também é recusado, porque percentil 0 ou 120 é pergunta mal feita. Dado ausente no dossiê aparece como lacuna nomeada, não como verde.

N3 · Slices: o agregado não absolve o segmento

Slice é o recorte que importa para alguém: checkout, busca, login — ou plano, região, dispositivo. Regressão que só aparece num slice some na média global: o agregado verde absolve o segmento vermelho se ninguém olhar por recorte. O oráculo AT-032 lista os slices com p99 acima do teto, em ordem: vazio é saúde segmentada, não sorte. Slice sem amostras cai no AT-031 — ausente, nunca zero.

"""Sinais que nao mentem: percentis de amostras brutas e regressao por slice.

Referencia executavel do Bloco 4.
Implementacao verbatim na folha B04-L. So STDLIB (math).
Oracalos LT04-T1-AT-030..032; carga/trafego real = trilha BLOCKED.
"""

from __future__ import annotations

import math


def percentil(amostras: list[float], p: float) -> float:
    """Nearest-rank sobre amostras brutas: sem amostra, erro explicito."""
    if not amostras:
        raise ValueError("sem amostras: percentil de vazio nao existe")
    if not 0.0 < p <= 100.0:
        raise ValueError(f"percentil invalido: {p}")
    ordenadas = sorted(amostras)
    posto = min(len(ordenadas), math.ceil(len(ordenadas) * p / 100.0))
    return ordenadas[posto - 1]


def resumo(amostras: list[float]) -> dict[str, float]:
    """Media mais cauda do mesmo raw: p50/p95/p99 acompanham n."""
    return {
        "n": float(len(amostras)),
        "media": sum(amostras) / len(amostras),
        "p50": percentil(amostras, 50.0),
        "p95": percentil(amostras, 95.0),
        "p99": percentil(amostras, 99.0),
    }


def taxa_erro(falhas: int, total: int) -> float:
    """Fracao de falhas: total zero e dado ausente, nao zero por cento."""
    if total <= 0:
        raise ValueError("total precisa ser positivo")
    return falhas / total


def slices_piores(p99_por_slice: dict[str, float], teto: float) -> list[str]:
    """Slices acima do teto, em ordem: agregado verde nao absolve segmento."""
    return sorted(s for s, p99 in p99_por_slice.items() if p99 > teto)

"""Comunicacao que vincula: quem aprova qual risco e revisor que reproduz.

Referencia executavel do Bloco 5.
Implementacao verbatim na folha B05-L. So STDLIB (sem imports).
Oracalos LT04-T1-AT-040..042; reuniao real = trilha BLOCKED.
"""

from __future__ import annotations

EXIGIDOS = {
    "medio": ["engenharia"],
    "alto": ["engenharia", "seguranca"],
    "critico": ["engenharia", "seguranca", "negocio"],
}


def exigidos(risco: str) -> list[str]:
    """Aprovadores do tier: tier desconhecido e erro, nao palpite."""
    if risco not in EXIGIDOS:
        raise ValueError(f"tier de risco desconhecido: {risco!r}")
    return list(EXIGIDOS[risco])


def aprovacao_ok(presentes: list[str], risco: str) -> bool:
    """Publica so com todos os exigidos presentes: risco sem dono bloqueia."""
    return all(p in presentes for p in exigidos(risco))


def reproducao_ok(registro: dict[str, object], digest: str, brutos: dict[str, object]) -> bool:
    """Revisor independente refaz do mesmo digest: claim sem bruto nao reproduz."""
    claims = registro.get("claims", [])
    return (
        registro.get("digest") == digest
        and isinstance(claims, list)
        and bool(claims)
        and all(str(c) in brutos for c in claims)
    )

Bloco 6 · Pós-mortem e aprendizado

Orientação: o que este bloco entrega

OrientaçãoO que será aprendido. Este bloco troca "não se repete" por aprendizado com dono, prazo e expiração. Três resultados saem daqui (LT04-T1-AT-050..052; ponte com spec B04/Q5):

  • registrar incidente com título, timeline e causas — sem os três, não há o que aprender (AT-050);
  • converter causa em ação com descrição, dono e prazo futuro — ação sem dono é intenção (AT-051);
  • tratar waiver como exceção com expiração — vencida, bloqueia o release em vez de prorrogá-lo sozinha (AT-052, ponte LT04-AT-033);
  • ler a referência executável — lab/posmortem_release.py — sem exigir incidente real. A execução pertence à folha B06-L, no Laboratório guiado LT04-T1.

Pré-requisitos. Blocos 1–5 (o incidente sempre cita versão, gate, stop, sinal e dono). Cada termo novo — pós-mortem, ação, waiver — é definido no ponto de uso. Todo exemplo é Python 3.14 com só stdlib. Nenhuma outra stack é pressuposta.

Saída observável. Ao fim da leitura, você registra com timeline, age com dono e prazo, e veta release com waiver vencida — e lê o contrato do lab/ sem precisar executá-lo aqui.

N1 · Registro: o fato antes da culpa

Pós-mortem é o registro escrito do incidente: título que nomeia o que doeu, timeline com fatos ordenados e causas que explicam sem apontar pessoa. Sem timeline, a discussão vira memória contra memória; sem causas, vira lista de sustos. O oráculo AT-050 acusa cada ausência pelo nome: título, timeline e causas ausentes aparecem separadas. Culpa individual não entra no registro — entra no máximo como falha de processo que permitiu o erro humano.

N2 · Ação: a causa com dono e prazo

Ação é a causa convertida em mudança: descrição do que muda, dono nomeado e prazo futuro em data ISO. Sem descrição, ninguém sabe o que fazer; sem dono, todos acham que é com outro; com prazo vencido ou ausente, a ação já nasceu morta. O oráculo AT-051 testa cada ausência isoladamente — quatro casos, quatro acusações. Ação aberta vira item condicional do Bloco 2: com dono, condição e expiração, ou não entra no release.

N3 · Waiver: a exceção que expira

Waiver é a exceção assinada: motivo escrito, dono nomeado e expiração datada. Exceção sem expiração é regra nova sem gate; vencida, bloqueia o release automaticamente — não pede prorrogação sozinha, exige nova decisão. O oráculo AT-052 cobra os três casos: válida com os três campos, vencida que veta, sem dono que veta. Waiver no dossiê aparece com validade consultável, nunca como "exceção permanente".

N4 · Falha e diagnóstico: o catálogo do aprendizado

Cada falha abaixo tem oráculo nomeado na folha B06-L: dado que reproduz, veredito calculado e conserto que fecha o vínculo. Pós-mortem sem ação com dono é o defeito raiz: o documento existe, a cerimônia aconteceu, e o próximo incidente cita o mesmo parágrafo.

"""Aprendizado com dono: registro, acao com prazo e waiver que expira de verdade.

Referencia executavel do Bloco 6.
Implementacao verbatim na folha B06-L. So STDLIB (sem imports).
Oracalos LT04-T1-AT-050..052; incidente real = trilha BLOCKED.
"""

from __future__ import annotations


def validar_registro(inc: dict[str, object]) -> list[str]:
    """Registro exige titulo, timeline com fatos e causas: sem um, nao aprende."""
    problemas = []
    if not str(inc.get("titulo", "")).strip():
        problemas.append("titulo ausente")
    timeline = inc.get("timeline", [])
    if not isinstance(timeline, list) or not timeline:
        problemas.append("timeline ausente")
    causas = inc.get("causas", [])
    if not isinstance(causas, list) or not causas:
        problemas.append("causas ausentes")
    return problemas


def validar_acao(acao: dict[str, object], hoje: str) -> list[str]:
    """Acao exige descricao, dono e prazo futuro: sem dono ou vencida, invalida."""
    problemas = []
    if not str(acao.get("descricao", "")).strip():
        problemas.append("descricao ausente")
    if not str(acao.get("dono", "")).strip():
        problemas.append("dono ausente")
    if str(acao.get("prazo", "")) < hoje:
        problemas.append("prazo ausente ou vencido")
    return problemas


def waiver_valida(waiver: dict[str, object], hoje: str) -> bool:
    """Waiver vale com motivo, dono e expiracao futura: vencida bloqueia release."""
    return (
        bool(str(waiver.get("motivo", "")).strip())
        and bool(str(waiver.get("dono", "")).strip())
        and str(waiver.get("expiracao", "")) >= hoje
    )

Leitura do resultado (exemplo variável, não evidência). validar_registro aprova o incidente completo e acusa timeline e causas ausentes. validar_acao aprova com descrição, dono e prazo futuro, e acusa cada ausência — incluindo prazo vencido. waiver_valida confirma com os três campos futuros e nega vencida ou sem dono.
