1.1 Padrão Python e ferramenta escolhida não são a mesma coisa

O ecossistema Python separa responsabilidades que o SDK do .NET concentra: interpretador, ambiente, metadata, build backend, resolvedor, lock, instalador, runner e registry. uv integra muitas dessas tarefas e é a implementação escolhida pelo curso, mas não define o padrão Python. pyproject.toml, wheel, sdist, entry points e pylock.toml pertencem à camada PyPA/especificações; pip, uv, Hatch, PDM ou Poetry podem consumir subconjuntos diferentes. O raciocínio profissional identifica primeiro o contrato e só depois o comando do adapter.

Contexto · O que um venv isola — e o que ele não prova

Um virtual environment fornece prefixo e diretório de instalação isolados para os pacotes do projeto. Dependendo da plataforma e da ferramenta, o executável pode ser cópia, link ou launcher; o contrato importante é sys.prefix/site-packages isolado, não “uma cópia completa do Python”. O uv normalmente gerencia .venv/ ao lado do projeto. Você ainda precisa saber qual interpretador executou o processo: confirme com sys.executable e sys.prefix, e nunca versione o ambiente.

Contexto · módulo, regular package e namespace package

Um arquivo .py pode fornecer um módulo; uma pasta com __init__.py fornece um regular package; e um namespace package pode existir sem esse arquivo. O sistema de import não é simples equivalência com o filesystem: finders e loaders usam sys.path, specs e o cache sys.modules. O nome de distribuição (csv-cleaner), o import package (python_senior_lab) e o comando instalado (csv-cleaner) são namespaces diferentes. Essa distinção será provada fora do checkout, não corrigida com sys.path.append().

Bloco 2 · Objetos, imports, recursos e exceções

2.1 Variável é nome ligado a objeto

Em Python, uma atribuição normalmente liga um nome a um objeto; ela não copia o objeto nem declara um slot com tipo fixo. Dois nomes podem apontar para a mesma lista, e mutar por um nome torna a mudança visível pelo outro. Reatribuir um dos nomes apenas troca seu binding.

original = ["a"]
alias = original
alias.append("b")
assert original == ["a", "b"]   # o mesmo objeto foi mutado

alias = ["x"]
assert original == ["a", "b"]   # só o nome alias foi religado
assert alias is not original

== pergunta igualdade de valor segundo o tipo; is pergunta identidade. Use is para singletons como None, não para comparar strings ou números. O hash precisa permanecer estável enquanto o objeto é chave de dicionário ou membro de set; por isso listas são não-hashable e uma dataclass mutável não ganha hash seguro automaticamente.

Default mutável. Expressões default são avaliadas quando a função é definida, não a cada chamada. def add(x, itens=[]) compartilha a mesma lista entre chamadas. Use None como sentinela ou factory em dataclasses/Pydantic.

2.2 Imutabilidade rasa não é isolamento

from dataclasses import dataclass

@dataclass(frozen=True, slots=True)
class Batch:
    ids: list[str]

b = Batch(ids=["A"])
b.ids.append("B")       # permitido: a LISTA interna continua mutável
# b.ids = []             # bloqueado: o atributo não pode ser religado

frozen=True impede atribuição normal aos campos; slots=True controla layout/atributos e pode reduzir memória. Nenhum deles produz imutabilidade profunda, atomicidade ou segurança entre threads. Se a invariante exige coleção imutável, use por exemplo tuple[str, ...] e teste a fronteira.

2.3 Import é busca, criação, execução e cache

Um arquivo .py é módulo. Um pacote regular contém __init__.py, mas Python também suporta namespace packages sem esse arquivo; portanto “toda pasta precisa de __init__.py” é uma regra de projeto possível, não definição da linguagem. Na primeira importação, o sistema procura uma spec, cria o módulo, o coloca em sys.modules e executa seu corpo. Importação possui efeitos e cache.

# errado: módulo de domínio importa CLI para reutilizar constante;
# CLI importa domínio para executar -> ciclo parcialmente inicializado.

# certo: mova o contrato compartilhado para um terceiro módulo estável.
from python_senior_lab.domain import SUPPORTED_CURRENCIES

Layout src/ ajuda a detectar import acidental do checkout, mas só a instalação do wheel em ambiente limpo prova que metadata e arquivos distribuídos estão corretos. Não “conserte” import com sys.path.append(); descubra se o erro é ambiente, instalação, nome do package, ciclo ou artefato incompleto.

2.4 Recursos e exceções formam um contrato

with garante a chamada de saída do context manager tanto no sucesso quanto na exceção. O equivalente mental de using ajuda, mas Python permite que __exit__ suprima a exceção; faça isso somente quando o contrato realmente considera a falha tratada.

from collections.abc import Iterator
from contextlib import contextmanager
from pathlib import Path

@contextmanager
def opened_utf8(path: Path) -> Iterator[object]:
    stream = path.open("r", encoding="utf-8", newline="")
    try:
        yield stream
    finally:
        stream.close()

def load_text(path: Path) -> str:
    try:
        with opened_utf8(path) as stream:
            return stream.read()  # type: ignore[attr-defined]
    except OSError as exc:
        raise RuntimeError(f"cannot read {path.name}") from exc

O exemplo explicita encoding/newline e preserva a causa com raise ... from exc. No laboratório, a porta será tipada com TextIO, eliminando o ignore usado aqui para tornar visível o problema: supressão de checker exige justificativa local e não pode esconder design incompleto.

3.3 Forma, estado e narrowing explícito

TypedDict descreve a forma estática de um mapping, mas não cria classe nem valida JSON. Literal restringe valores conhecidos; Self preserva o subtipo em APIs fluentes; Never torna exhaustiveness verificável. Para narrowing, prefira checks que o checker entende. TypeIs refina os ramos verdadeiro e falso quando o tipo retornado é compatível; TypeGuard refina principalmente o ramo verdadeiro e admite transformações mais flexíveis. Um cast não verifica nada em runtime: ele é uma afirmação sua ao checker.

from typing import Literal, Never, TypedDict, TypeIs


class RawTransaction(TypedDict):
    id: str
    amount: str
    source: Literal["csv", "webhook"]


def is_non_empty_text(value: object) -> TypeIs[str]:
    return isinstance(value, str) and bool(value.strip())


def assert_never(value: Never) -> Never:
    raise AssertionError(f"caso não tratado: {value!r}")

3.4 Variance é uma propriedade da relação, não decoração

Um produtor somente de T pode ser covariante; um consumidor somente de T pode ser contravariante; uma coleção mutável que lê e escreve tende a ser invariante. Copiar a intuição de IEnumerable<out T> para list[T] é inseguro: se list[Dog] servisse como list[Animal], alguém poderia inserir um Cat. Modele a direção da informação e peça ao checker para rejeitar a substituição plantada.

3.5 Annotations diferidas no Python 3.14

Python 3.14 muda a avaliação de annotations e oferece annotationlib para recuperá-las em formatos apropriados. Código de framework não deve depender de avaliar nomes arbitrários por acidente. O laboratório compara __annotations__ com annotationlib.get_annotations() e testa uma forward reference sem importar a dependência prematuramente.

Fundamento de engenharia · Tipagem nominal vs. estrutural — recicle a teoria

Sistemas de tipos podem combinar relações nominais e estruturais. Em C#, interfaces de aplicação são normalmente nominais: o tipo declara : Y. Um Python Protocol permite compatibilidade estrutural: o tipo serve quando expõe os membros com assinaturas compatíveis, sem herança explícita. O consumidor pode declarar o menor contrato de que precisa e adaptar bibliotecas de terceiros; isso reduz acoplamento nominal, mas não elimina a obrigação de provar substituibilidade por testes e semântica.

3.6 Protocol e substituibilidade estrutural

from typing import Protocol


class Notificador(Protocol):
    """O CONSUMIDOR define o contrato que precisa. Ninguém 'implementa' isto."""

    def enviar(self, destino: str, mensagem: str) -> bool: ...


class EmailNotificador:          # repare: NÃO herda de Notificador
    def enviar(self, destino: str, mensagem: str) -> bool:
        print(f"email para {destino}: {mensagem}")
        return True


def alertar(n: Notificador, destino: str) -> None:
    n.enviar(destino, "alerta!")


alertar(EmailNotificador(), "denisson@exemplo.com")  # mypy: OK — a forma bate
alertar("uma string", "x")                           # mypy: erro — str não tem .enviar

O ... (reticências) no corpo é literal — é o "sem implementação" do Python, como o ; de um método de interface. E o teste decisivo: rode uv run mypy --strict nesse arquivo com a última linha e veja o erro antes de executar — o runtime nunca foi tocado.

3.7 Onde a analogia com C# quebra

  • Hints não validam runtime. Uma base com annotations sem checker pode transmitir falsa confiança. O gate declara checker e versão; a trust boundary continua precisando de parsing/validação.
  • Any é contagioso. Um Any entra numa expressão, a expressão inteira vira Any, e o mypy silencia dali em diante. É o dynamic do C#: uma gota tinge o copo. Strict mode existe para te obrigar a estancar isso nas fronteiras.
  • Sem sobrecarga de método real. Um nome = uma função. @overload existe só para o verificador; em runtime é a última definição que vale. O idioma pythônico é parâmetro com default ou union: def buscar(chave: int | str) -> ...
  • Variáveis não têm tipo; valores têm. x = 1 seguido de x = "a" é legal em runtime (mypy reclama). A disciplina vem do verificador, não da linguagem.
  • Mutabilidade default. Não há readonly/init; convenção + Final, frozen=True em dataclass, e o verificador. Prefixo _ é o "private por contrato social" — não existe enforcement de acesso.

4.1 Validação runtime começa por uma fronteira explícita

JSON de request, linha de CSV, resposta de API externa e saída de LLM chegam em runtime; o checker não observou esses valores. Pydantic é uma implementação forte para transformar dado não confiável em estrutura tipada e erros localizados. Ele não substitui autorização, regra de negócio, consistência entre registros nem prova que todo caminho de construção validou.

Tradução .NET

Pydantic combina parsing, coerção, validação e serialização de modo parecido com peças de DTO, serializer e validator no .NET. A analogia termina aí: model_construct() cria sem validação, atribuições não são revalidadas por padrão e validadores não conhecem invariantes externas. A afirmação correta é: uma instância produzida por um caminho de validação satisfez as regras executadas naquele momento.

Fundamento de engenharia · Parse, don't validate — e a fronteira de confiança

Dois fundamentos clássicos que o Pydantic materializa — recicle-os, porque com LLMs eles viram sobrevivência:

  • Parse, don't validate: converta dado cru para uma representação mais específica e pare de carregar o formato ambíguo. Isso reduz estados inválidos; não elimina bypass, mutação, concorrência ou invariantes que dependem de banco/serviço.
  • Fronteira de confiança (trust boundary): a linha em que proveniência, privilégios ou garantias mudam. Usuário, rede, arquivo e saída de LLM devem ser tratados segundo ameaça e contrato. Pydantic pode ser um adapter de parsing nessa borda; autenticação, autorização, limites, invariantes e sanitização de efeitos pertencem a controles próprios.

from datetime import date

class Transacao(BaseModel):
    """Uma linha do extrato — o contrato da fronteira de ingestão."""

    model_config = ConfigDict(
        frozen=True,          # impede reatribuição normal; não congela objetos internos
        extra="forbid",       # campo desconhecido = erro (não ignore silencioso!)

    descricao: str = Field(min_length=1, max_length=200)
    valor: Decimal = Field(gt=0)                  # > 0, validado na construção
    categoria: str | None = None                  # opcional com default
    tags: list[str] = Field(default_factory=list) # default mutável: SEMPRE factory

        """Restrição local de entrada; regra de negócio pode exigir outra camada."""
        if "@" in v:
            raise ValueError("descrição não pode conter e-mail")
        return v
Contexto · decoradores — o @ em cima das funções

Um decorador (@nome) é uma função que recebe a função/classe abaixo e devolve uma versão modificada — açúcar sintático para sem_pii_obvia = field_validator("descricao")(sem_pii_obvia). O paralelo .NET mais próximo é o atributo ([Authorize]), mas com uma diferença central: atributo é metadado passivo que outro código lê por reflection; decorador executa e transforma no momento da definição. Você vai vê-los em todo lugar: @app.get(...) no FastAPI, @pytest.fixture, @dataclass. Quando vir @, leia: "esta definição passa por uma transformação antes de existir".

Os três verbos que você vai digitar mil vezes:

4.3 Coerção, strictness e caminhos sem validação

Em modo laxo, Pydantic aplica conversões documentadas; em modo estrito, reduz coerções. Tolerância não é automaticamente boa: escolha por proveniência, ambiguidade, compatibilidade e impacto do erro. O exemplo abaixo torna a política explícita:

class TransacaoEstrita(Transacao):
    model_config = ConfigDict(frozen=True, extra="forbid", strict=True)

TransacaoEstrita.model_validate({"valor": "10.5", ...})  # ValidationError: esperava Decimal, veio str

Não existe regra universal “CSV laxo, serviço estrito”. Decida por origem, ambiguidade tolerada, custo do erro e compatibilidade do contrato. Uma conversão explícita antes do model costuma ser superior a coerções surpreendentes escondidas.

5.1 Scheduling cooperativo e ownership

Uma coroutine só progride quando é aguardada ou transformada em Task. Um event loop executa uma Task de cada vez em sua thread e alterna quando ela aguarda um Future/I/O. Bloqueio síncrono impede outras Tasks daquele loop de avançar; uma aplicação pode ter vários workers, processos, threads ou interpreters. O diagnóstico precisa nomear a fronteira afetada em vez de dizer que “o Python inteiro congelou”.

No .NET, Task é uma abstração de operação assíncrona; nem toda Task “roda no ThreadPool”. No asyncio, Task agenda uma coroutine no loop corrente. Em ambos os ecossistemas, bloquear uma thread crítica reduz capacidade; as mecânicas de scheduler, synchronization context, workers e cancelamento diferem.

A regra dos dois mundos, que resolve 90% das decisões:

  • Não bloqueie o loop. Para API síncrona inevitável, confirme thread safety, imponha limite e use to_thread/executor. Cancelar o await não mata magicamente o trabalho na thread.
  • Verifique o contrato da biblioteca: prefira API async quando o recurso a oferece; para API síncrona, confirme bloqueio, thread safety, propagação de contexto e limite do executor. O nome do pacote sozinho não prova o comportamento.

5.2 TaskGroup, cancelamento e limites

import asyncio


async def transform(item: str) -> str:
    await asyncio.sleep(0)  # ponto cooperativo local e determinístico
    return item.upper()


async def process_all(items: list[str]) -> list[str]:
    tasks: list[asyncio.Task[str]] = []
    async with asyncio.TaskGroup() as group:
        tasks = [group.create_task(transform(item), name=item) for item in items]
    return [task.result() for task in tasks]


if __name__ == "__main__":
    print(asyncio.run(process_all(["brl", "usd"])))

Leia o fluxo antes de decorar a sintaxe. async def declara uma função assíncrona; chamá-la cria uma corrotina, ainda sem executar o corpo. await asyncio.sleep(0) cria um ponto cooperativo: esta Task devolve o controle ao loop e pode retomar depois. TaskGroup() delimita o lifetime das Tasks criadas em seu bloco; se o bloco termina, elas já concluíram ou falharam segundo a política do grupo. A compreensão [group.create_task(...) for item in items] cria uma Task nomeada para cada item e guarda as referências. Por fim, task.result() lê o valor de uma Task já concluída, e asyncio.run(...) cria e fecha o loop para um programa de linha de comando. O vínculo entre essas linhas é ownership: toda execução iniciada tem quem a aguarde, cancele e inspecione.

Três diferenças que merecem teste na transição de .NET
  1. Corrotina fria: resultado = buscar_cotacao(client, "USD") sem await não busca nada — devolve um objeto corrotina inerte (o warning coroutine was never awaited é isso). Em C#, chamar método async já dispara; em Python, não.
  2. Fire-and-forget sem referência: asyncio.create_task(foo()) sem guardar o retorno pode ser coletado pelo GC no meio da execução. Guarde a referência (ou use TaskGroup, abaixo).
  3. gather vs. exceções: por padrão, a primeira exceção é propagada ao await; as demais awaitables não são canceladas. TaskGroup cancela siblings quando uma tarefa falha e reúne falhas em ExceptionGroup.
async def process_all(items: list[str]) -> list[str]:
    tasks: list[asyncio.Task[str]] = []
    try:
        async with asyncio.timeout(2):
            async with asyncio.TaskGroup() as group:
                tasks = [group.create_task(process_one(x), name=x) for x in items]
    except asyncio.CancelledError:
        # cleanup local em finally; cancelamento continua sendo sinal de controle
        raise
    return [task.result() for task in tasks]

Coroutines usam try/finally para liberar recursos. Engolir CancelledError pode quebrar TaskGroup e asyncio.timeout(). Para backpressure, semaphore limita uma região; asyncio.Queue(maxsize=N) também limita quantos itens aguardam e faz o produtor esperar quando o consumidor satura.

6.1 O GIL é parte da decisão, não a decisão inteira

CPython padrão e build free-threaded. No build padrão, o GIL impede execução simultânea de bytecode Python por múltiplas threads no mesmo interpretador, embora I/O e extensões nativas possam liberar o lock. O build free-threaded é suportado no Python 3.14, mas isso não torna código automaticamente seguro ou mais rápido: extensões podem reabilitar o GIL, estado compartilhado ainda exige sincronização e overhead pode dominar a carga.
import sys
import sysconfig


def runtime_capabilities() -> dict[str, object]:
    is_free_threaded_build = bool(sysconfig.get_config_var("Py_GIL_DISABLED"))
    is_gil_enabled = sys._is_gil_enabled()  # Python 3.14 / CPython
    return {
        "free_threaded_build": is_free_threaded_build,
        "gil_enabled_now": is_gil_enabled,
    }

Este é um probe, não uma recomendação automática. runtime_capabilities() é uma função sem argumentos que devolve um dicionário: as chaves são textos, e os valores podem ter tipos diferentes, por isso a anotação usa dict[str, object]. A primeira pergunta é sobre o build: ele foi compilado com suporte a free-threading? A segunda é sobre esta execução: o GIL está efetivamente ligado agora? Registrar as duas respostas evita concluir que uma flag de instalação prova o comportamento de uma extensão carregada depois.

Registre as duas dimensões. Ter suporte no build não prova que o GIL permaneça desabilitado durante toda a execução. A capability é dado de observação, não feature flag presumida.

6.3 Capacidade não é um número fora da fronteira do sistema

A Lei de Little, L = λW, vale para sistema estável quando as três medidas usam a mesma fronteira e janela. Em um batch fechado de 50 itens, “50 criados” não significa que 50 estão simultaneamente em serviço: parte pode estar na fila. Meça separadamente itens admitidos, executando e aguardando; então use a lei para verificar coerência, não para inventar throughput. Filas bounded, semáforos e rate limits controlam admissão; não eliminam a capacidade necessária.

7.2 Context managers: gestão determinística, não equivalência mágica

from pathlib import Path

# C#: using var reader = new StreamReader(path);
with open("dados.csv", encoding="utf-8") as f:
    conteudo = f.read()
# fecha aqui, mesmo com exceção; o protocolo não é idêntico a IDisposable

# vários recursos, um with:

    destino.write(origem.read())

A ponte útil: em C#, using opera sobre o contrato de descarte; em Python, o protocolo síncrono usa __enter__/__exit__ e o assíncrono usa __aenter__/__aexit__. Ambos buscam cleanup determinístico, mas RAII estrito vincula aquisição ao lifetime do objeto e não é equivalência exata com with. Um context manager também pode ser criado por gerador:

from collections.abc import Iterator
from contextlib import contextmanager
import time


@contextmanager
def cronometro(rotulo: str) -> Iterator[None]:
    inicio = time.perf_counter()
    try:
        yield                                # <- aqui roda o corpo do with
    finally:
        print(f"{rotulo}: {time.perf_counter() - inicio:.3f}s")


with cronometro("parse do csv"):
    processar_arquivo()

Você vai usar esse padrão para transação de banco (M03), span de tracing (M06) e orçamento de tokens (M05). A versão assíncrona usa async with e possui contrato próprio de entrada/saída.

7.3 Geradores: preguiça, ownership e memória

from collections.abc import Iterator


def linhas_validas(caminho: str) -> Iterator[str]:
    """Lê um CSV de 10 GB usando memória de UMA linha."""
    with open(caminho, encoding="utf-8") as f:
        for linha in f:                      # arquivo é iterável linha a linha
            limpa = linha.strip()
            if limpa and not limpa.startswith("#"):
                yield limpa                  # entrega e PAUSA, como yield return

O modelo mental é o mesmo do IEnumerable preguiçoso do LINQ: nada roda até alguém consumir, e o pipeline processa item a item. As pegadinhas também são as mesmas — e mais uma:

  • Um gerador se esgota. Iterou duas vezes? A segunda vem vazia, sem erro. (O IEnumerable do LINQ re-executa; o gerador do Python não.) Precisa de duas passadas → materialize: list(gen).
  • Preguiça + recurso = armadilha: se o with do arquivo fechar antes de o consumidor iterar, explode. Consuma dentro do escopo ou desenhe a função para possuir o recurso (como acima).

from dataclasses import dataclass, field

Uma heurística útil é validar dados externos em um modelo de fronteira e representar dados internos com dataclass, mapping, tuple ou classe conforme comportamento e invariantes. Dataclass gera métodos; não valida tipos por si. frozen=True bloqueia atribuição de campos, mas não congela objetos internos, e hash só existe quando a combinação de opções/campos permite. slots=True restringe atributos declarados e pode reduzir memória, mas compatibilidade, herança e mensuração continuam parte da decisão.

7.6 Pattern matching: despacho pela forma, sem esconder contrato

def rotular(evento: dict[str, object]) -> str:
    match evento:
        case {"tipo": "pagamento", "valor": int(v)} if v > 100_000:
            return f"pagamento grande: {v}"
        case {"tipo": "pagamento"}:
            return "pagamento comum"
        case {"tipo": "estorno", "motivo": str(m)}:
            return f"estorno: {m}"
        case _:
            return "desconhecido"

É o switch com pattern do C# 9+, com o mesmo espírito (inclusive guards com if). Uso legítimo: despachar sobre a FORMA de dado semi-estruturado — payloads de webhook, mensagens de agente, respostas de LLM (M05/M08 usam bastante). Para dois casos, um if simples continua mais claro.

Fundamento de engenharia · ownership, mutabilidade e semântica de referência
  • Gestão determinística: GC não substitui o fechamento oportuno de conexão, arquivo e lock. using e with respondem ao mesmo risco com protocolos diferentes; try/finally torna o ownership explícito.
  • Imutabilidade exige profundidade definida: bloquear rebinding de campo não torna uma lista interna imutável nem elimina corrida. Declare a fronteira, prefira valores imutáveis quando fizer sentido e teste hash/aliasing.
  • Nomes são ligados a objetos. Atribuir b = a não copia o objeto; mutabilidade determina se o alias observa mudanças. Um default [] é avaliado na definição e reutilizado. == delega igualdade ao tipo; is testa identidade e é apropriado para singletons como None.

7.7 Prática guiada · Refatorar sem perder operabilidade

1Receba o código com sotaque. Use a fixture de defeito em fixtures/generated_defects/; ela funciona no caso feliz, mas concentra estado e manejo manual de arquivo: 
class CsvProcessor:
    def __init__(self):
        self.lines = []

    def LoadFile(self, path):
        f = open(path, "r", encoding="utf-8")
        raw = f.readlines()
        f.close()
        result = []
        i = 0
        while i < len(raw):
            line = raw[i].strip()
            if len(line) > 0:
                if not line.startswith("#"):
                    result.append(line)
            i = i + 1
        self.lines = result
        return result

    def GetTotals(self):
        totals = {}
        for i in range(len(self.lines)):
            parts = self.lines[i].split(";")
            cat = parts[0]
            val = int(parts[1])
            if cat in totals:
                totals[cat] = totals[cat] + val
            else:
                totals[cat] = val
        return totals
2Refatore você mesmo (sem IA — é você quem está treinando o sotaque) aplicando o bloco inteiro: with (ou gerador) para o arquivo; comprehension/gerador no filtro; for parts in ... direto em vez de índice (range(len(...)) é a placa de "vim do C#"); dict.get/defaultdict ou Counter na soma; snake_case; type hints completos; e a pergunta de design: essa classe precisa existir, ou são duas funções puras? (Dica: não precisa. Classe sem estado que valha a pena é namespace caro — em Python, módulo já é namespace.)

Resultado esperado: o contrato se mantém com menos estado, tipos estritos e testes de arquivo grande. Não existe meta de linhas; legibilidade, memória e comportamento são os oráculos.

3Adicione operabilidade. Leia e escreva com encoding="utf-8" e política explícita de newline; envie resultado para stdout, diagnóstico para stderr e use exit codes documentados. Inclua um correlation id no log, preserve exception chain com raise ... from exc e registre tempo com perf_counter_ns() e pico de memória com tracemalloc.

Resultado esperado: testes por subprocesso separam stdout/stderr, validam bytes UTF-8 e exit code. O caso grande conserva memória compatível com streaming e o erro aponta causa original.

Síntese do bloco 7
  • with expressa gestão determinística; a analogia com using ajuda, mas os protocolos não são idênticos.
  • Gerador = IEnumerable preguiçoso que se esgota; memória O(1) para arquivo de qualquer tamanho.
  • Comprehension = LINQ nativo; uma cláusula de cada, senão vira função.
  • Pydantic, dataclass, mapping e classe resolvem responsabilidades diferentes; frozen é superficial e default mutável exige factory.
  • Tudo é referência; == é Equals, is é ReferenceEquals (só para None); typo em atributo CRIA atributo — slots barra.

8.1 Pytest: comportamento antes da implementação

Funções e classes de teste são convenções de coleta, e assert é reescrito durante importação/coleta para oferecer diagnóstico rico. Isso não torna a suíte boa por si: o oráculo deve distinguir comportamento correto de uma implementação plausível, mas errada.

from decimal import Decimal

import pytest
from python_senior_lab.parsing import parse_decimal


def test_parse_valor_com_virgula() -> None:
    assert parse_decimal("1.234,56") == Decimal("1234.56")


def test_parse_valor_vazio_explode() -> None:
    with pytest.raises(ValueError, match="valor vazio"):   # Assert.Throws
        parse_decimal("")


@pytest.mark.parametrize(                                   # [Theory]/[InlineData]
    ("bruto", "esperado"),
    [
        ("10", Decimal("10")),
        ("10,5", Decimal("10.5")),
        ("1.000,00", Decimal("1000.00")),
    ],
)
def test_parse_valor_formatos(bruto: str, esperado: Decimal) -> None:
    assert parse_decimal(bruto) == esperado

8.2 Fixtures: composição, escopo e teardown

A fixture é onde pytest deixa o xUnit para trás. Em vez de construtor/IClassFixture, você declara funções-provedoras e os testes pedem pelo nome do parâmetro — injeção por nome, com escopo, teardown e composição:

from collections.abc import Iterator
from pathlib import Path

import pytest


@pytest.fixture
def csv_sujo(tmp_path: Path) -> Path:
    """tmp_path é fixture BUILTIN: pasta temporária única por teste, autolimpa."""
    arquivo = tmp_path / "dados.csv"
    arquivo.write_text(
        "categoria;valor\nmercado;100\n\n# comentário\nfarmacia;abc\n",
        encoding="utf-8",
    )
    return arquivo


@pytest.fixture
def config_estrita() -> Iterator[Config]:
    cfg = Config(modo="estrito")
    yield cfg                    # antes do yield = Arrange; depois = Dispose/teardown
    cfg.limpar()


def test_ingestao_reporta_linha_invalida(csv_sujo: Path, config_estrita: Config) -> None:
    resultado = ingerir(csv_sujo, config_estrita)      # pediu 2 fixtures pelo nome
    assert resultado.rejeitadas == 1
    assert "farmacia" in resultado.erros[0].linha

O que fixtures dão que o xUnit faz suar: composição (fixture usa fixture — csv_sujo usa tmp_path), escopos (scope="session" para o container de Postgres caro que sobe uma vez — M03 usa), conftest.py (fixtures compartilhadas por pasta, sem import), e override em camadas (o teste de integração redefine a fixture db do unitário). Async? pytest-asyncio: marque async def test_... e pronto (config asyncio_mode = "auto" no pyproject).

Fundamento de engenharia · A pirâmide de testes na era da IA

Recicle a pirâmide (muitos unitários rápidos, alguns de integração, poucos E2E) com a correção de 2026: quando a IA escreve o código, os testes mudam de papel — de rede de segurança para ESPECIFICAÇÃO EXECUTÁVEL. O agente otimiza para "testes verdes"; se os testes são fracos, ele produz código fraco aprovado. Consequências práticas: (1) teste de caminho triste e borda valem MAIS que o de caminho feliz — é onde a IA erra; (2) cobertura % é métrica de vaidade, mutação de comportamento é o que conta (o teste falharia se o comportamento mudasse?); (3) você escreve/revisa os testes com mais atenção do que o código — é o item 3 do seu contract.md (M01); (4) teste que testa implementação (mock de tudo, assert em chamada interna) quebra a cada refactor da IA e ensina você a ignorá-lo — teste comportamento pela interface pública.

8.3 Property tests, controle negativo e defeitos de IA

Exemplos verificam casos conhecidos; propriedades relacionam muitas entradas e saídas. Para o parser, uma propriedade útil é: toda transação aceita, serializada e lida novamente preserva moeda e valor decimal. Outra: linhas rejeitadas nunca aparecem no CSV limpo. Hypothesis gera e minimiza contraexemplos; fixe perfil, versões e seed apenas quando investigar reprodução.

from decimal import Decimal

from hypothesis import given, strategies as st


@given(st.decimals(allow_nan=False, allow_infinity=False, places=2))
def test_decimal_round_trip(value: Decimal) -> None:
    encoded = format(value, "f")
    assert parse_decimal(encoded) == value
Teste do teste. Remova uma regra crítica, troque o sinal de uma comparação ou use uma fixture defeituosa de fixtures/generated_defects/. Se a suíte continuar verde, o oráculo está fraco. O catálogo de defeitos de IA deve ser revisado por tipo, semântica e risco operacional — “parece Python” não é evidência.

Conclusão — o essencial em 8 linhas

Comece pelo padrão; uv é o adapter do laboratório.
Hints não validam runtime; checker, configuração e testes cobrem classes diferentes de falha.
Pydantic valida somente nos caminhos executados; regra de domínio continua explícita.
Um event loop coopera em sua thread; bloqueio, ownership e cancelamento têm escopo mensurável.
Threads, processos, interpreters e free-threading são decisões de workload, não slogans.
Geradores, context managers e estruturas de dados carregam contratos de lifetime e mutabilidade.
Teste é especificação executável; propriedade, caso negativo e mutação desafiam código de IA.
Distribuição só está entregue quando o wheel funciona fora do source tree.
